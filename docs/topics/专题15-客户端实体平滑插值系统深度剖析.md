## 一、引言与导读

### 1.1 本专题的定位

Filter 系统是 BigWorld 客户端"看得见的灵魂"。在一个跨越 CellApp / BaseApp / Client 三层、由数千个实体共存的虚拟世界里,**网络层只能提供离散的、按距离调节频率的位置采样**;而**渲染层则需要每帧 60Hz 的连续位置与朝向**。两者之间的鸿沟,正是 Filter 系统的用武之地。

> **核心问题:如何用稀疏且不均匀到达的位置采样,驱动每帧都连续、可信、不撕裂的实体表现?**

BigWorld 14.4.1 用一套 **"历史缓冲 + 延迟插值 + 自适应 Latency + 误差盒钳制 + 坐标系自动换算"** 的体系来回答这个问题。这套体系既不是简单的线性插值,也不是单纯的外推,而是一种**带误差约束的、向后看的(Look-behind)插值重放系统**,核心思想类似 GSL(Valve 的 Game State Lobby)/ Snapshot Interpolation,但又融入了 BigWorld 自有的 Volatile 误差盒、坐标系切换、车辆搭乘等 MMOG 特色。

## 二、平滑插值概述与设计哲学

### 2.1 为什么需要平滑插值

#### 2.1.1 网络更新的离散性 vs 渲染的连续性

BigWorld 的 MMOG 网络模型有四个本质特征:

1. **离散到达**:服务器对每个实体的 volatile 更新按固定 tick(默认 10Hz,即每 100ms 一次)发出,且不会在两个 tick 之间补充任何中间状态。
2. **频率自适应**:离玩家越远的实体,更新频率越低,远端实体的更新间隔可达数秒(详见专题6 AOI UpdateScheme)。
3. **不可靠传输**:volatile 数据走 UDP 不可靠通道,允许丢包、乱序(详见专题7 Mercury)。
4. **误差压缩**:位置使用"玩家相对压缩 + 误差盒"机制,远端实体的位置精度可能低至 ±10m。

而渲染层要求:

1. **每帧 30~60Hz** 的位置输出;
2. **视觉连续性**:不能出现瞬移、抖动、撕裂;
3. **朝向平滑**:转向时不能瞬间甩头,避免动画机撕裂;
4. **可预测性**:玩家应能直观感知"实体正在朝某方向移动"。

二者之间存在巨大鸿沟。如果客户端"傻直通"地把每次网络采样直接赋给模型矩阵,会出现:

- **跳变(Jitter)**:每次更新位置瞬间跳 1m,画面卡顿;
- **回退(Rewind)**:乱序包导致实体位置倒退;
- **远端实体超慢**:由于更新稀疏,远端实体几乎不动;
- **瞬移式转向**:朝向瞬间旋转 180°,动画撕裂;
- **穿地/悬空**:误差压缩 + 落地时机的不同步,导致实体脱离地面。

Filter 系统就是解决这一切的"软垫"。

#### 2.1.2 网络抖动的来源

```
服务器 tick (10Hz)         ─●───●───●───●───●───●───●───●─
                            │   │   │   │   │   │   │   │
                            │   └packet loss (丢包)
                            │       │
                            └─delay spike (延迟尖峰)
                                    │
客户端接收 (无序、不均)       ●─●─────●─●─●─────●───●──●─●
                            ↑       ↑       ↑       ↑
                            乱序     缺失     乱序     缺失

渲染帧 (60Hz)              ─│─│─│─│─│─│─│─│─│─│─│─│─│─│─│─│
                            ↑ 每帧都需连续位置
```

抖动来自三处:

| 抖动源 | 表现 | 应对策略 |
|--------|------|----------|
| **网络抖动** | 包到达间隔从 100ms 到 800ms 波动 | Latency 自适应,延迟自动调整 |
| **包丢失** | 期望的采样缺失 | 历史缓冲多帧冗余,缺失不影响插值 |
| **包乱序** | 后发的包先到 | `time` 时间戳过滤,旧包丢弃 |

#### 2.1.3 插值 vs 外推

主流的两大平滑流派:

- **插值(Interpolation,向后看)**:用过去 N 个采样合成"现在"的位置,需要 Latency 缓冲,绝对不会预测错,但永远落后于服务器。
- **外推(Extrapolation,向前看)**:用最近的采样+速度预测未来位置,无需缓冲,瞬时响应好,但预测时间长了会偏离,需要纠偏。

BigWorld AvatarFilter 选择的是**插值为主 + 少量外推补偿**的混合策略:

- 默认情况下,以 `time - latency` 在历史缓冲中插值;
- 当 `time - latency` 超过最新采样时间(即"超前"),会做小幅外推(用相邻采样的速度线性延伸);
- 通过 Latency 自适应让缓冲"刚刚好够用",既保证平滑又尽量减少延迟感。

### 2.2 与传统 MMOG 平滑方案的对比

#### 2.2.1 传统 MMOG 的"位置插值"做法

许多早期 MMOG 引擎采用朴素做法:

```cpp
// 简陋版:每次收到位置,线性插值过去
void OnPositionUpdate(Vector3 newPos) {
    moveStart_ = currentPos_;
    moveEnd_ = newPos;
    moveTime_ = 0;
    moveDuration_ = 100ms;  // 假设下次更新间隔
}
void Update(float dt) {
    moveTime_ += dt;
    float t = clamp(moveTime_ / moveDuration_, 0, 1);
    currentPos_ = lerp(moveStart_, moveEnd_, t);
}
```

缺点:

- 假设"下次更新恰好 100ms 后到",但实际抖动大,容易出现"刚到达 moveEnd_ 又来了新位置 → 跳变";
- 没有处理丢包/乱序;
- 没有误差盒概念,精度低时会出现"假精度"。

#### 2.2.2 BigWorld AvatarFilter 的做法

BigWorld 的设计目标更宏大:

1. **历史缓冲**:保存最近 8 个采样,可在任意时刻回放历史;
2. **时间对齐**:输出位置的时间是 `gameTime - latency`,而不是 `gameTime`,保证永远有历史数据可插值;
3. **自适应 Latency**:Latency 根据最近包间隔动态调整,既不过大(延迟感)也不过小(撞墙);
4. **误差盒钳制**:Waypoint 不能跳出网络层给出的误差盒,避免插值结果偏到不合理的位置;
5. **坐标系统自动切换**:实体上车/下车时,历史 Waypoint 自动转换坐标系,无需重置;
6. **回调机制**:可以在历史时间线"到达"某个时间点时触发 Python 回调(用于音效、特效等时序敏感事件)。

这种设计带来明显优势:

| 维度 | 传统插值 | BigWorld AvatarFilter |
|------|----------|----------------------|
| 包丢失 | 跳变 | 仍能平滑(Latency 内还有历史) |
| 包乱序 | 位置回退 | 时间戳过滤,旧包丢弃 |
| 抖动 | 速度忽快忽慢 | Latency 自适应,速度均匀 |
| 误差精度 | 假精度 | 误差盒钳制,诚实表达 |
| 上下车 | 需重置 | 自动坐标变换 |
| 时序事件 | 难同步 | 回调机制精准 |

### 2.3 设计哲学小结

BigWorld Filter 的设计哲学可以归纳为三条:

1. **"宁可延迟,不可错位"**:接受一定的视觉延迟,换取绝对的视觉平滑;
2. **"网络层说什么就信任什么,但渲染层用历史说话"**:网络层采样被信任地放入历史,渲染层只看历史;
3. **"自适应优于固定值"**:Latency、Error Box、坐标变换都动态自适应,而不是硬编码。

### 3.3 三种调用节奏

Filter 系统涉及三类不同节奏的调用:

| 节奏 | 调用者 | 调用方法 | 频率 |
|------|--------|----------|------|
| **网络 tick** | 网络层收到包时 | `input()` | 10Hz(近端) ~ 0.1Hz(远端) |
| **渲染 tick** | 客户端主循环 | `output()` | 30~60Hz |
| **重置/瞬移** | 服务器/脚本 | `reset()` | 罕见 |

`input` 与 `output` 完全解耦,这正是 Filter 系统能化解抖动的关键:**输入与输出异步,中间用历史缓冲桥接**。

## 五、MovementFilter 基类接口剖析

### 5.1 接口定义

`MovementFilter` 是所有 Filter 的抽象基类,定义在 `lib/connection/movement_filter.hpp`。它是 BWEntity 与具体 Filter 实现之间的契约。

```cpp
// lib/connection/movement_filter.hpp:17-108
class MovementFilter
{
public:
    virtual BWENTITY_API ~MovementFilter() {}

    virtual void reset( double time ) = 0;

    virtual void input( double time, SpaceID spaceID, EntityID vehicleID, 
        const Position3D & position, const Vector3 & positionError,
        const Direction3D & direction ) = 0;

    virtual void output( double time, MovementFilterTarget & target ) = 0;

    virtual bool getLastInput( double & time, SpaceID & spaceID, 
        EntityID & vehicleID, Position3D & position, Vector3 & positionError,
        Direction3D & direction ) const = 0;

    bool filterDropPoint( SpaceID spaceID, const Position3D & fall,
```

### 5.2 四个核心纯虚方法

#### 5.2.1 `reset(double time)`

**职责**:使 Filter 失效,丢弃所有历史,直到下一次 `input` 时重新初始化。

**调用时机**:
- 服务器发送 `isTeleport = true` 的位置更新(瞬移);
- 客户端发生空间切换、车辆切换;
- Python 脚本主动调用 `BigWorld.Filter.reset(time)`。

**实现约定**:
- 不真正"清空",而是设置 `reset_ = true` 标志;
- 真正的清空发生在下一次 `input` 时,以新输入填充所有 StoredInput。

#### 5.2.2 `input(time, spaceID, vehicleID, pos, posError, dir)`

**职责**:接收一次网络采样,加入 Filter 内部状态。

**参数含义**:

| 参数 | 类型 | 含义 |
|------|------|------|
| `time` | `double` | 客户端估算的"该采样发出时"的客户端时间 |
| `spaceID` | `SpaceID` | 实体所在空间 ID |
| `vehicleID` | `EntityID` | 实体所搭乘的车辆 ID,`NULL_ENTITY_ID` 表示在世界坐标 |
| `pos` | `Position3D` | 位置,在 vehicle 局部或世界坐标(已解码) |
| `posError` | `Vector3` | 误差盒三轴半径 |
| `dir` | `Direction3D` | 朝向(yaw/pitch/roll) |

**调用频率**:10Hz(近端)~ 0.1Hz(远端),取决于 AOI UpdateScheme(详见专题6)。

#### 5.2.3 `output(time, target)`

**职责**:把 Filter 当前估算的实体状态写入 `target`(即 Entity)。

**调用频率**:每渲染帧 1 次(30~60Hz),由 `BWEntities::tick` 触发。

**关键约定**:`time` 是当前客户端 gameTime,Filter 内部会以 `time - latency` 实际查询历史。

#### 5.2.4 `getLastInput(...)`

**职责**:查询最近一次 `input` 收到的数据,主要用于 Filter 切换时状态拷贝。

**返回值**:`true` 表示有数据,`false` 表示从未收到输入。

### 5.3 状态拷贝机制:`copyState` 与 `tryCopyState`

当 Filter 被替换时(例如从 AvatarFilter 切换到 DumbFilter),新 Filter 需要继承旧 Filter 的状态,避免位置回退。

```cpp
// lib/connection/movement_filter.cpp:28-51
void MovementFilter::copyState( const MovementFilter & rOtherFilter )
{
    BW_GUARD;
    // 1. 优先尝试让子类自己处理(多态)
    if (this->tryCopyState( rOtherFilter ))
    {
        return;
    }
    // 2. 兜底:从 rOtherFilter 取出最近一次 input,作为自己的第一次 input
    double time;
    SpaceID spaceID;
    EntityID vehicleID;
    Position3D position;
    Vector3 positionError;
    Direction3D direction;
    if (rOtherFilter.getLastInput( time, spaceID, vehicleID, position,
        positionError, direction ) )
    {
        this->input( time, spaceID, vehicleID, position, positionError,
            direction );
    }
}
```

`tryCopyState` 是模板方法模式的钩子:

- 基类默认返回 `false`,触发兜底逻辑;
- `AvatarFilter::tryCopyState` 用 `dynamic_cast` 检查对方是否也是 `AvatarFilter`,是则拷贝整个 `helper_`(完整历史 + Waypoint);
- `BoidsFilter::tryCopyState` 进一步拷贝 `boidData_` 等群集状态;
- `AvatarDropFilter::tryCopyState` 拷贝 `alignToGround_`、`groundNormal_`。

这种设计既保证类型安全(同类型间完整拷贝),又允许异类型间至少不丢位置(兜底)。

### 5.4 委托给 FilterEnvironment 的方法

`MovementFilter` 还把"需要外部世界信息"的操作委托给 `FilterEnvironment`:

| 方法 | 用途 |
|------|------|
| `filterDropPoint` | 从某点垂直下落,与地形/障碍求交,得到落点 |
| `resolveOnGroundPosition` | 判断 y < -12000 是"onGround"占位,采样地形高度 |
| `transformIntoCommon` | 从 vehicle 局部坐标 → 世界坐标 |
| `transformFromCommon` | 从世界坐标 → vehicle 局部坐标 |

这种委托让 Filter 本身不直接依赖 Entity/Space/Chunk,便于单元测试与跨进程复用(例如 `bwentity` 库可以在工具进程里跑)。

### 6.2 BWClientFilterEnvironment 实现

#### 6.2.1 `filterDropPoint`

```cpp
// client/bwclient_filter_environment.cpp:90-133
bool BWClientFilterEnvironment::filterDropPoint(
        SpaceID spaceID, const Position3D & startPosition,
        Position3D & landPosition, Vector3 * pGroundNormal )
{
    Position3D adjustedStartPosition = startPosition;
    adjustedStartPosition.y += 0.1f;          // 抬高 10cm 避免自交

    SolidCollisionCallback scc;
    landPosition = adjustedStartPosition;

    // 加微量偏移避免 collision 误差
    adjustedStartPosition.x += 0.005f;
    adjustedStartPosition.z += 0.005f;

    SmartPointer< ClientSpace > pSpace = SpaceManager::instance().space( spaceID );
    if (pSpace == NULL) return false;

    Position3D endPosition( adjustedStartPosition );
    endPosition.y -= maxFilterDropPointDistance_;   // 默认 100m

    pSpace->collide( adjustedStartPosition, endPosition, scc );

    if (scc.distance() < 0.f) return false;     // 没命中

    if (pGroundNormal != NULL)
    {
        *pGroundNormal = scc.triangle().normal();
        pGroundNormal->normalise();
    }

    landPosition.y -= scc.distance();
    return true;
}
```

**算法步骤**:

1. 起点 `startPosition` 抬高 10cm,避免起点正好贴在表面导致自交;
2. 加 5mm 偏移到 x/z,避免浮点精度边界问题;
3. 用 `ClientSpace::collide` 做 ray-cast,起点 → 终点(下方 100m);
4. 用 `SolidCollisionCallback` 收集"最近命中",跳过 `TRIANGLE_NOCOLLIDE` 标志的非碰撞三角形;
5. 返回命中距离与法线。

#### 6.2.2 `resolveOnGroundPosition`

```cpp
// client/bwclient_filter_environment.cpp:136-157
bool BWClientFilterEnvironment::resolveOnGroundPosition( Position3D & position,
        bool & isOnGround )
{
    isOnGround = false;

    if (position.y < -12000.0f)    // "onGround" 占位标记
    {
        float terrainHeight =
            Terrain::BaseTerrainBlock::getHeight( position.x, position.z );

        if (terrainHeight == Terrain::BaseTerrainBlock::NO_TERRAIN)
        {
            return false;
        }

        position.y = terrainHeight;
        isOnGround = true;
    }
    return true;
}
```

**关键魔法数字 `-12000.0f`**:服务器在 volatile 更新中,如果只想表达"在地面上",会把 y 设置为约 -13000 的占位值,客户端见到这个值就采样地形高度。`filter.hpp` 头注释中明确:

> The network layer will sometimes provided positions that are 'on ground' and will need to have their y coordinate sampled from the terrain at the given (x,z). They will appear as positions with a y component approximately equal to -13000.

#### 6.2.3 `transformIntoCommon` / `transformFromCommon`

```cpp
// client/bwclient_filter_environment.cpp:160-184

        EntityID vehicleID, Position3D & position, Direction3D & direction )
```

`vehicleID == NULL_ENTITY_ID` 时(`findEntity` 返回 NULL),位置/朝向就是世界坐标,直接不变。否则用车辆实体的变换矩阵做坐标变换。注意 `BWEntity::transformVehicleToCommon` 只是把 yaw 累加(pitch/roll 注释掉了,这是历史遗留):

```cpp
// lib/connection_model/bw_entity.cpp:423-440
void BWEntity::transformVehicleToCommon( Position3D & position, 
    Direction3D & direction ) const
{
    Matrix m;
    const Direction3D vehicleDirection = this->direction();
    m.setRotate( vehicleDirection.yaw, vehicleDirection.pitch,
        vehicleDirection.roll );
    position = m.applyVector( position ) + this->position();
```

### 6.3 FilterEnvironment 的设计意图

把环境访问抽象成接口有三个好处:

1. **解耦**:`AvatarFilterHelper` 在 `lib/connection/` 库中,不依赖客户端的 `Entity`/`Space`/`Chunk`,可独立编译、单元测试;
2. **复用**:`bwentity` 库可在工具进程(模型查看器、回放器)中复用 Filter,只需要换一个 `FilterEnvironment` 实现;
3. **可测试**:单测时可注入 mock FilterEnvironment,精确控制地形/车辆变换行为。

**`wpOwner_` 是弱引用**:Python `PyFilter` 对象的生命周期可能比 C++ `Filter` 长(Filter 可能先被销毁),弱引用避免悬垂。

### 9.2 PyFilter 包装层的设计意图

Python 侧的 `Filter` 对象(`BigWorld.AvatarFilter()` 等)与 C++ 侧的 `Filter` 实例**生命周期不同步**:

- **Python 长生命周期**:Python 脚本可能把 `AvatarFilter` 对象存在变量里多次复用;
- **C++ 短生命周期**:C++ `Filter` 与 Entity 绑定,Entity 离开 AoI 时 Filter 被销毁。

`PyFilter` 的职责就是**适配这两种生命周期**:

```cpp
// client/py_filter.hpp:32-101
class PyFilter : public PyObjectPlusWithWeakReference
{
    Py_Header( PyFilter, PyObjectPlusWithWeakReference )

public:
    PyFilter( PyTypeObject * pType );
    virtual ~PyFilter();

    virtual Filter * pAttachedFilter() { return pAttachedFilter_; }
    virtual const Filter * pAttachedFilter() const
        { return pAttachedFilter_; }

    void onFilterDestroyed( Filter * pDestroyedFilter );

    bool isAttached() const { return isAttached_; }
    void isAttached( bool newValue ) { isAttached_ = newValue; }

    Filter * getFilter();

    // Python 接口
    PY_AUTO_METHOD_DECLARE( RETVOID, reset,
        OPTARG( double, PyFilter::getTimeNow(), END ) );

protected:
    static double getTimeNow();

private:
    void reset( double time );

    // 子类必须实现:工厂方法,创建一个新的 C++ Filter
    virtual Filter * getNewFilter() = 0;

    // 子类可重写:Filter 即将被销毁,缓存其配置
    virtual void onLosingAttachedFilter() {}

    Filter * pAttachedFilter_;     // 弱引用(不拥有)
    bool isAttached_;
};
```

### 9.3 PyFilter 工作流程

```
Python 脚本:                          C++ 侧:
  f = BigWorld.AvatarFilter()  ──→   new PyAvatarFilter()
  entity.filter = f            ──→   PyEntity::filter setter
                                         │
                                         │ 调用 PyFilter::getFilter()
                                         ▼
                                    getNewFilter() [子类实现]
                                         │
                                         │ new AvatarFilter(this)
                                         ▼
                                    pAttachedFilter_ = ...
                                         │
                                         │ 转交给 BWEntity
                                         ▼
                                    BWEntity::pFilter(pNewFilter)
                                         │
                                         │ (Filter 被销毁时)
                                         ▼
                                    Filter::~Filter()
                                         │
                                         │ wpOwner_->onFilterDestroyed(this)
                                         ▼
                                    PyFilter::onFilterDestroyed()
                                         │
                                         │ 触发 onLosingAttachedFilter() (在销毁前)
                                         ▼
                                    pAttachedFilter_ = NULL
                                         │
                                         │ Python 脚本可继续用 f 给其他 Entity
                                         ▼

```

### 9.4 PyFilter::getFilter 实现细节


每次调用都创建**新的** C++ Filter 实例。这意味着同一个 Python `PyAvatarFilter` 可以挂到多个 Entity 上,每个 Entity 拿到独立的 C++ Filter。

### 10.5 input 实现

`input` 实现的核心是**误差盒信任策略**:

```cpp
// client/dumb_filter.cpp:109-167
void DumbFilter::input( double time, SpaceID spaceID, EntityID vehicleID,
                        const Position3D & pos, const Vector3 & posError,
                        const Direction3D & dir )
{
    BW_GUARD;

    // 1. 旧包过滤(乱序保护)
    if (time < time_)
    {
        return;
    }

    time_ = time;

    BoundingBox thisErrorBox( pos - posError, pos + posError );

    if (spaceID_ != spaceID || vehicleID_ != vehicleID ||
        almostEqual( posError_, posError ))
    {
        // 2a. 坐标系变化 或 误差精度相同 → 直接信任新输入
        spaceID_ = spaceID;
        vehicleID_ = vehicleID;
        pos_ = pos;
        posError_ = posError;
    }
    else if (thisErrorBox.intersects( pos_ ))
    {
        // 2b. 误差盒变化但旧位置仍在新的误差盒内 → 不移动,保留更精确的误差
        if (posError.lengthSquared() < posError_.lengthSquared())
        {
            posError_ = posError;
        }
    }
    else
    {
        // 2c. 误差盒变化且旧位置已不在新误差盒内 → 不得不信任新输入(可能视觉跳变)
        pos_ = pos;
        posError_ = posError;
    }

    dir_ = dir;
}
```

#### 10.5.1 三种误差盒场景的语义

```
场景 2a:坐标系变化 或 误差精度未变
                                         
    old pos •                               
           ┌─── error box (old) ───┐       
           │                        │       
           └────────────────────────┘       
    new pos •  ← 直接跳到新位置               
           ┌─── error box (new) ───┐       
           │                        │       
           └────────────────────────┘       

场景 2b:误差盒变化,旧位置在新盒内
                                         
    old pos •                               
           ┌─── error box (old, 较大) ──┐  
           │                              │  
           │      ┌── error (new, 较小) ─┐│  
           │      │                      ││  
           │      └──────────────────────┘│  
           │                              │  
           └──────────────────────────────┘  
    new pos   ← 不动,保留更精确的误差盒        

场景 2c:误差盒变化,旧位置不在新盒内
                                         
    old pos •  ← 已不在新盒内               
           ┌─── error box (old, 较大) ──┐  
           │                              │  
           └──────────────────────────────┘  
                                         
                 new pos •  ← 跳到新位置    
                 ┌── error (new, 较小) ─┐   
                 │                      │   
                 └──────────────────────┘   
```

**含义**:
- 场景 2b 表达"服务器精度提高了,但我们仍在可信范围内"——避免不必要的视觉跳变;
- 场景 2c 是不可避免的跳变,但只有在精度真的提升且旧位置已被淘汰时才发生。

### 10.6 output 实现

`output` 的核心是**地形高度采样**:

```cpp
// client/dumb_filter.cpp:178-218
void DumbFilter::output( double time, MovementFilterTarget & target )
{
    BW_GUARD;
    static DogWatch dwDumbFilterOutput("DumbFilter");
    dwDumbFilterOutput.start();

    Entity & entity = static_cast< Entity & >( target );

    // 1. 处理 onGround 占位(y < -12000)
    if (pos_.y < -12000.f)
    {
        float oldY = entity.localPosition().y;
        pos_.y = (oldY < -12000.f) ?  90.f : oldY + 1.f;

        Position3D rpos;
        if (this->filterDropPoint( spaceID_, pos_, rpos ))
        {
            pos_.y = rpos.y;
        }
        else
        {
            float terrainHeight =
                Terrain::BaseTerrainBlock::getHeight( pos_.x, pos_.z );

            if (terrainHeight != Terrain::BaseTerrainBlock::NO_TERRAIN)
            {
                pos_.y = terrainHeight;
            }
            else
            {
                WARNING_MSG( "DumbFilter::output: Could not get terrain\n" );
            }
        }
    }

    target.setSpaceVehiclePositionAndDirection( spaceID_, vehicleID_, pos_,
        dir_ );

    dwDumbFilterOutput.stop();
}
```

**算法步骤**:

1. 如果 y < -12000(onGround 占位):
   - 取实体当前 y 或抬高 90m 作为起点;
   - 用 `filterDropPoint` 做碰撞检测,得到落点;
   - 若失败,fallback 到 `Terrain::BaseTerrainBlock::getHeight`(更轻量的纯地形查询);
   - 仍失败则警告。
2. 把 `spaceID/vehicleID/pos/dir` 写入 target。

**注意**:`DumbFilter::output` **不输出速度**——因为不维护历史,无法估计速度。

### 10.7 DumbFilter 的适用场景

| 场景 | 选用 DumbFilter 的理由 |
|------|------------------------|
| 服务器瞬移 | 瞬移本就不该平滑,直接跳到目标位置 |
| UI 实体 | UI 实体(如小地图标记)不需要平滑 |
| 调试/可视化的辅助实体 | 简单可靠,不需要复杂逻辑 |
| 低带宽模式 | 远端实体不需要平滑,节省 CPU |
| AvatarFilter 失效时的退化 | 通过 `s_isActive_ = false` 切换 |

| 维度 | 普通实体(AvatarFilter) | 玩家实体(PlayerAvatarFilter) |

```
                                                    │

                                                    │
```

服务器对玩家的位置更新总是 `isTeleport = true`(强制重置),因为没有 Latency,直接覆盖本地位置即可。

## 十二、AvatarFilter 核心过滤器剖析

### 12.1 AvatarFilter 类定义

```cpp

                        const Direction3D & dir );
```

### 12.2 AvatarFilter 的核心特征

1. **历史缓冲**:通过 `AvatarFilterHelper helper_` 持有 8 个 StoredInput;
2. **延迟插值**:每次 output 用 `time - latency_` 查询历史;
3. **回调列表**:`callbackListHead_` 维护时间回调链表;
4. **可继承的钩子**:`onEntityPositionUpdated` 让子类(AvatarDropFilter)在 output 后调整位置;
5. **状态可拷贝**:`tryCopyState` 重写,允许 AvatarFilter 间互相拷贝历史。

### 12.3 构造与析构

```cpp
// client/avatar_filter.cpp:57-86
AvatarFilter::AvatarFilter( PyAvatarFilter * pOwner ) :
    Filter( pOwner ),
    helper_( this->environment() ),
    callbackListHead_()
{
    BW_GUARD;
    callbackListHead_.setAsRoot();
}

AvatarFilter::~AvatarFilter()
{
    BW_GUARD;
    // 析构所有未触发的 callback
    while (callbackListHead_.getNext() != &callbackListHead_)
    {
        ListNode * pFirstNode = callbackListHead_.getNext();
        AvatarFilterCallback * pFirstCallback =
            AvatarFilterCallback::getFromListNode( pFirstNode );
        pFirstCallback->removeFromList();
        bw_safe_delete( pFirstCallback );
    }
}
```

`callbackListHead_.setAsRoot()` 把链表头初始化为自循环节点。析构时遍历链表,删除所有未触发的 callback(防止泄漏)。

### 12.4 input/output 委托

`AvatarFilter` 的 `input` 完全委托给 `helper_`:


`output` 委托后,还做了**回调触发**:

```cpp
// client/avatar_filter.cpp:145-216
void AvatarFilter::output( double time, MovementFilterTarget & target )
{
    BW_GUARD;
    static DogWatch dwAvatarFilterOutput("AvatarFilter");
    dwAvatarFilterOutput.start();

    Entity & entity = static_cast< Entity & >( target );

    SpaceID     resultSpaceID;
    EntityID    resultVehicleID;
    Position3D  resultPosition;
    Vector3     resultVelocity;
    Direction3D resultDirection;

    // 1. 委托给 helper_ 做插值
    double outputTime = helper_.output( time, resultSpaceID, resultVehicleID,
        resultPosition, resultVelocity, resultDirection );

    // 2. 写入 Entity
    target.setSpaceVehiclePositionAndDirection( resultSpaceID,
        resultVehicleID, resultPosition, resultDirection );
    entity.localVelocity( resultVelocity );

    // 3. 等待车辆中则提前返回
    if (entity.waitingForVehicle())
    {
        dwAvatarFilterOutput.stop();
        return;
    }

    // 4. 让子类(AvatarDropFilter)有机会修改位置
    this->onEntityPositionUpdated( entity );

    dwAvatarFilterOutput.stop();

    // 5. 触发所有该触发的 callback
    while (callbackListHead_.getNext() != &callbackListHead_)
    {
        ListNode * pFirstNode = callbackListHead_.getNext();
        AvatarFilterCallback * pFirstCallback =
            AvatarFilterCallback::getFromListNode( pFirstNode );

        // 还没到时间,停止
        if (pFirstCallback->targetTime() > outputTime)
        {
            break;
        }

        // 触发 callback
        if ( pFirstCallback->triggerCallback( outputTime ) )
        {
            // callback 返回 true:把实体"快照"到 callback 时刻
            helper_.extract( pFirstCallback->targetTime(), resultSpaceID,
                resultVehicleID, resultPosition, resultVelocity,
                resultDirection );

            target.setSpaceVehiclePositionAndDirection( resultSpaceID,
                resultVehicleID, resultPosition, resultDirection );
            entity.localVelocity( resultVelocity );

            this->onEntityPositionUpdated( entity );
        }

        pFirstCallback->removeFromList();
        bw_safe_delete( pFirstCallback );
    }
}
```

**关键设计**:

1. **DogWatch 性能计数**:用 `static DogWatch dwAvatarFilterOutput`,统计 AvatarFilter 的耗时;
2. **回调与位置同步**:callback 触发后,可以选择把实体"快照"到 callback 时刻,用于精准时序事件(如脚步声对齐);
3. **链表按时间排序**:回调链表按 `targetTime` 升序,一旦遇到未到时间的就停止;
4. **回调自动清理**:触发后从链表移除并 `delete`。

### 12.5 tryCopyState 状态拷贝

```cpp
// client/avatar_filter.cpp:263-309
bool AvatarFilter::tryCopyState( const MovementFilter & rOtherFilter )
{
    const AvatarFilter * pOtherAvatarFilter =
        dynamic_cast< const AvatarFilter * >( &rOtherFilter );

    if (pOtherAvatarFilter == NULL)
    {
        return false;   // 不是 AvatarFilter,让基类走兜底
    }

    helper_ = pOtherAvatarFilter->helper_;     // 拷贝整个历史

    // 清空自己的 callback 链表
    while (callbackListHead_.getNext() != &callbackListHead_)
    {
        ListNode * pFirstNode = callbackListHead_.getNext();
        AvatarFilterCallback * pFirstCallback =
            AvatarFilterCallback::getFromListNode( pFirstNode );
        pFirstCallback->removeFromList();
        bw_safe_delete( pFirstCallback );
    }

    // 窃取对方的 callback(假设对方即将销毁)
    ListNode * pNode = pOtherAvatarFilter->callbackListHead_.getNext();
    while (pNode != &pOtherAvatarFilter->callbackListHead_)
    {
        AvatarFilterCallback * pCallback =
            AvatarFilterCallback::getFromListNode( pNode );
        pNode = pNode->getNext();
        pCallback->removeFromList();
        MF_ASSERT( pNode->getPrev() == &pOtherAvatarFilter->callbackListHead_ );
        this->addCallback( pCallback );
    }

    return true;
}
```

**注释说**:"We assume the other filter is going away and we want to take over its callbacks. This holds as the only current caller of this code is `BWEntity::pFilter()` which immediately deletes pOtherAvatarFilter"。

这个窃取行为依赖一个前提:旧的 Filter 即将被销毁,所以窃取它的 callback 不会造成"两个 Filter 同时拥有同一 callback"的双重释放。

### 12.6 NUM_STORED_INPUTS = 8

`AvatarFilterHelper::NUM_STORED_INPUTS = 8`(见 `lib/connection/avatar_filter_helper.hpp:16`)。

为什么是 8?

- **足够冗余**:即使突发丢包 5~6 个,仍有历史可插值;
- **不太占内存**:每个 StoredInput 约 80 字节,8 个约 640 字节;
- **3 是不够的**:突发抖动很容易超过 3 帧;
- **16 是浪费**:大多数情况下用不到那么多。

这是经验值,不可配置(编译期常量)。

## 十四、StoredInput 数据结构深度剖析

### 14.1 StoredInput 结构

```cpp
// lib/connection/avatar_filter_helper.hpp:50-60
class StoredInput
{
public:
    double      time_;
    SpaceID     spaceID_;
    EntityID    vehicleID_;
    Position3D  position_;
    Vector3     positionError_;
    Direction3D direction_;
    bool        onGround_;
};
```

| 字段 | 类型 | 字节 | 含义 |
|------|------|------|------|
| `time_` | `double` | 8 | 客户端估算的发出时间 |
| `spaceID_` | `SpaceID`(uint32) | 4 | 空间 ID |
| `vehicleID_` | `EntityID`(uint32) | 4 | 车辆 ID |
| `position_` | `Position3D`(Vector3) | 12 | 位置 |
| `positionError_` | `Vector3` | 12 | 误差盒三轴半径 |
| `direction_` | `Direction3D` | 24 | yaw/pitch/roll |
| `onGround_` | `bool` | 1 | 是否被服务器标记为 onGround |

考虑到对齐与填充,实际单个 StoredInput 约 64~80 字节。`storedInputs_[8]` 共约 640 字节。

### 14.2 环形缓冲机制

`storedInputs_` 是固定大小数组,通过 `currentInputIndex_` 实现**环形缓冲**:

```cpp
// lib/connection/avatar_filter_helper.cpp:742-749
AvatarFilterHelper::StoredInput & AvatarFilterHelper::getStoredInput( uint index )
{
    BW_GUARD;
    MF_ASSERT( index < NUM_STORED_INPUTS );
    return storedInputs_[(currentInputIndex_ + index) % NUM_STORED_INPUTS];
}
```

`index = 0` 是最新的,`index = NUM_STORED_INPUTS - 1` 是最旧的。**`currentInputIndex_` 永远指向最新的写入位置**。

#### 14.2.1 写入时的环形后退

```cpp
// lib/connection/avatar_filter_helper.cpp:318-319
currentInputIndex_ = (currentInputIndex_ + NUM_STORED_INPUTS - 1) %
    NUM_STORED_INPUTS;
```

为什么是 `+ NUM_STORED_INPUTS - 1` 而不是 `- 1`?因为 C++ 的 `%` 对负数实现不确定,先 `+ N` 保证非负再 `% N` 是惯用法。

#### 14.2.2 环形缓冲示意

```
初始状态(全部初始化为相同数据):
  storedInputs_: [_, _, _, _, _, _, _, _]
                  0  1  2  3  4  5  6  7
  currentInputIndex_ = 0
  getStoredInput(0..7) → storedInputs_[0..7]

收到第一个 input (reset_ = true):
  全部填为 input0
  storedInputs_: [I0, I0, I0, I0, I0, I0, I0, I0]
  currentInputIndex_ = 0

收到第二个 input:
  currentInputIndex_ = (0 + 8 - 1) % 8 = 7
  storedInputs_[7] = I1
  storedInputs_: [I0, I0, I0, I0, I0, I0, I0, I1]
                                    newest ↑
  getStoredInput(0) = storedInputs_[7] = I1  ✓
  getStoredInput(1) = storedInputs_[0] = I0  ✓
  getStoredInput(2) = storedInputs_[1] = I0  (旧的)

收到第三个 input:
  currentInputIndex_ = (7 + 7) % 8 = 6
  storedInputs_[6] = I2
  storedInputs_: [I0, I0, I0, I0, I0, I0, I2, I1]
                              newest ↑
```

环形缓冲的好处:**O(1) 写入,无内存分配**,适合高频调用。

### 14.3 time_ 单调性保证

```cpp
// lib/connection/avatar_filter_helper.cpp:313-316
if (time <= this->getStoredInput( 0 ).time_)
{
    return;
}
```

如果新 input 的 `time` 不大于最新 StoredInput 的 `time`,直接丢弃。这处理了**乱序包**——后到达的"旧"包不会污染历史。

注意是 `<=` 而不是 `<`,因为相同时间戳的重复包也应丢弃。

### 14.4 inputCount_ 的作用

```cpp
// lib/connection/avatar_filter_helper.cpp:334
++inputCount_;
```

`inputCount_` 是累计收到的 input 数(单调递增,不回退)。它用于:

1. 在 `output` 中计算 `maxLatencyFrame`:

```cpp
// lib/connection/avatar_filter_helper.cpp:364
const int maxLatencyFrame = std::min( inputCount_, (uint)NUM_STORED_INPUTS ) - 1;
```

意思是"用最近多少个 input 估算 idealLatency"。如果 `inputCount_ < 8`(还没收够),用 `inputCount_` 本身;否则用 `8`。

2. 决定 idealLatency 计算能否进行:

```cpp
// lib/connection/avatar_filter_helper.cpp:366-367
if (maxLatencyFrame > 0)
{
    // ... 计算 idealLatency_
}
```

只有收到至少 2 个 input 后,才能估算包间隔,计算 idealLatency。

## 十五、Waypoint 数据结构与坐标变换

### 15.1 Waypoint 结构

```cpp
// lib/connection/avatar_filter_helper.hpp:76-89
class Waypoint
{
public:
    double          time_;
    SpaceID         spaceID_;
    EntityID        vehicleID_;
    Position3D      position_;
    Direction3D     direction_;
    StoredInput     storedInput_;

    void changeCoordinateSystem( FilterEnvironment & environment,
        SpaceID spaceID, EntityID vehicleID );
};
```

`Waypoint` 是 AvatarFilter 插值的"端点"。每次 `chooseNextWaypoint` 产生新的 `nextWaypoint_`,旧的 `nextWaypoint_` 变成 `previousWaypoint_`。

### 15.2 Waypoint 与 StoredInput 的区别

| 维度 | StoredInput | Waypoint |
|------|-------------|----------|
| 来源 | 网络层直接采样 | Filter 计算/钳制后 |
| 数量 | 8 个(固定) | 2 个(prev, next) |
| 误差盒 | 原始误差 | 已被钳制/调整 |
| 坐标系 | 各自的(可能不同车辆) | **同一个**(next 的坐标系) |
| 用途 | 历史记录 | 插值端点 |

**关键点**:相邻两个 Waypoint 总是在**同一个坐标系**中,这样才能直接做线性插值。`chooseNextWaypoint` 中会做坐标系变换。

### 15.3 changeCoordinateSystem 实现

```cpp
// lib/connection/avatar_filter_helper.cpp:422-441
void AvatarFilterHelper::Waypoint::changeCoordinateSystem(
        FilterEnvironment & environment, SpaceID spaceID,
        EntityID vehicleID )
{
    BW_GUARD;

    if (spaceID_ == spaceID && vehicleID_ == vehicleID)
    {
        return;     // 已经在目标坐标系
    }

    // 1. 从自己的坐标系 → 世界坐标
    environment.transformIntoCommon( spaceID_, vehicleID_, position_,
        direction_ );

    // 2. 更新 spaceID_/vehicleID_
    spaceID_ = spaceID;
    vehicleID_ = vehicleID;

    // 3. 从世界坐标 → 目标坐标系
    environment.transformFromCommon( spaceID_, vehicleID_, position_,
        direction_ );
}
```

**算法步骤**:

1. 如果已经同坐标系,直接返回(优化);
2. `transformIntoCommon`:转世界坐标;
3. 更新 spaceID/vehicleID;
4. `transformFromCommon`:从世界转目标坐标系。

这种"经过世界中转"的方法确保任意两个坐标系间都能转换。

### 15.4 上车/下车时的坐标变换示例

```
状态:实体在地面上行走,vehicleID = NULL_ENTITY_ID
  storedInputs_: 全部在世界坐标
  nextWaypoint_ / previousWaypoint_: 世界坐标

事件:实体上车,服务器发来 vehicleID = VEHICLE_ID 的新 input

input(time, space, VEHICLE_ID, vehicleLocalPos, ...):
  storedInputs_[0] = new input  (vehicle 局部坐标)

下一次 output → extract → chooseNextWaypoint:
  previousWaypoint_.changeCoordinateSystem(env, nextInput.spaceID_, VEHICLE_ID)
    → world → vehicle 局部
  nextWaypoint_     .changeCoordinateSystem(env, nextInput.spaceID_, VEHICLE_ID)
    → world → vehicle 局部

  newWaypoint 的坐标系自然就是 VEHICLE_ID 的局部坐标(因为 nextInput 是)

结果:插值在 vehicle 局部坐标中完成,实体跟着车辆移动。
```

注意:**CoordinateSystem 变换发生在每次 chooseNextWaypoint**,这意味着即使历史 StoredInput 来自不同坐标系,Waypoint 也会被统一到同一个坐标系下,保证插值正确。

## 十六、input 方法工作流程

### 16.1 input 完整源码

```cpp
// lib/connection/avatar_filter_helper.cpp:299-335
void AvatarFilterHelper::input( double time, SpaceID spaceID,
    EntityID vehicleID, const Position3D & position,
    const Vector3 & positionError, const Direction3D & direction )
{
    BW_GUARD;

    // 1. 处理 reset 状态
    if (reset_)
    {
        this->resetStoredInputs( time, spaceID, vehicleID, position,
            positionError, direction );
        reset_ = false;
        return;
    }

    // 2. 乱序保护:旧包丢弃
    if (time <= this->getStoredInput( 0 ).time_)
    {
        return;
    }

    // 3. 环形后退一格,腾出新位置
    currentInputIndex_ = (currentInputIndex_ + NUM_STORED_INPUTS - 1) %
        NUM_STORED_INPUTS;

    // 4. 写入新的 StoredInput
    StoredInput & storedInput = this->getStoredInput( 0 );

    storedInput.time_ = time;
    storedInput.spaceID_ = spaceID;
    storedInput.vehicleID_ = vehicleID;
    storedInput.position_ = position;
    storedInput.positionError_ = positionError;
    storedInput.direction_ = direction;

    // 5. 处理 onGround 占位(采样地形高度)
    this->resolveOnGroundPosition( storedInput.position_,
        storedInput.onGround_ );

    // 6. 通知 output 有新数据
    gotNewInput_ = true;
    ++inputCount_;
}
```

### 16.2 算法步骤详解

#### 步骤 1:reset 处理

如果 `reset_` 为 true(刚被 reset 或刚构造),把所有 8 个 StoredInput 全部填为这次 input 的值,然后清 reset_。详见 §16.3。

#### 步骤 2:乱序保护

```cpp
if (time <= this->getStoredInput( 0 ).time_)
{
    return;
}
```

`getStoredInput(0).time_` 是当前最新 StoredInput 的时间。如果新 input 的 `time` 不大于它,丢弃。

**为什么 `<=` 而不是 `<`?** 相同时间戳的重复包(可能来自重传或抖动)也丢弃,避免覆盖。

#### 步骤 3:环形后退

```cpp
currentInputIndex_ = (currentInputIndex_ + NUM_STORED_INPUTS - 1) % NUM_STORED_INPUTS;
```

把 `currentInputIndex_` 后退一格,使得 `getStoredInput(0)` 现在指向"空"的位置(实际上是原来最老的位置,被覆盖)。

#### 步骤 4:写入 StoredInput

把新 input 的字段写入 `storedInputs_[currentInputIndex_]`,现在它就是最新的(索引 0)。

#### 步骤 5:onGround 解析

```cpp
this->resolveOnGroundPosition( storedInput.position_, storedInput.onGround_ );
```

如果 `position_.y < -12000`(服务器占位),采样地形高度替换。`onGround_` 标志记下"这是 onGround 输入",供后续 `output` 判断是否需要做地形投影。

#### 步骤 6:通知与计数

```cpp
gotNewInput_ = true;
++inputCount_;
```

`gotNewInput_` 让下次 `output` 知道"有新数据,要重新计算 idealLatency_"。`inputCount_` 单调递增。

### 16.3 resetStoredInputs 实现

```cpp
// lib/connection/avatar_filter_helper.cpp:444-486
void AvatarFilterHelper::resetStoredInputs( double time,
        SpaceID spaceID, EntityID vehicleID, const Position3D & position,
        const Vector3 & positionError, const Direction3D & direction )
{
    BW_GUARD;
    const float NONZERO_TIME_DIFFERENCE = 0.01f;

    currentInputIndex_ = 0;
    inputCount_ = 0;
    gotNewInput_ = true;
    timeOfLastOutput_ = time;

    bool onGround = false;
    Position3D correctedPosition = position;

    this->resolveOnGroundPosition( correctedPosition, onGround );

    // 把所有 8 个 StoredInput 填为相同值,只是 time 递减 0.01s
    for (uint i = 0; i < NUM_STORED_INPUTS; ++i)
    {
        StoredInput & storedInput = this->getStoredInput( i );
        storedInput.time_ = time - (i * NONZERO_TIME_DIFFERENCE);  // 避免零时间差
        storedInput.spaceID_ = spaceID;
        storedInput.vehicleID_ = vehicleID;
        storedInput.position_ = correctedPosition;
        storedInput.positionError_ = positionError;
        storedInput.direction_ = direction;
        storedInput.onGround_ = onGround;
    }

    latency_ = AvatarFilterSettings::s_latencyFrames_ * NONZERO_TIME_DIFFERENCE;

    // 初始化 Waypoint
    nextWaypoint_.time_ = time - NONZERO_TIME_DIFFERENCE;
    nextWaypoint_.spaceID_ = spaceID;
    nextWaypoint_.vehicleID_ = vehicleID;
    nextWaypoint_.position_ = position;
    nextWaypoint_.direction_ = direction;

    previousWaypoint_ = nextWaypoint_;
    previousWaypoint_.time_ -= NONZERO_TIME_DIFFERENCE;
}
```

#### 16.3.1 NONZERO_TIME_DIFFERENCE 的含义

如果所有 StoredInput 的 time_ 都相同,后续插值时会除零(`alpha = (time - prev.time) / (next.time - prev.time)` 会除以 0)。

为了避免,把 8 个 StoredInput 的 time_ 设置为 `time, time - 0.01, time - 0.02, ..., time - 0.07`。这些是"虚拟时间",仅用于让插值数学合法。在实际收到第 2、3 个真实 input 之前,Filter 行为近似"原地不动"。

#### 16.3.2 latency_ 初始化

```cpp
latency_ = AvatarFilterSettings::s_latencyFrames_ * NONZERO_TIME_DIFFERENCE;
// 默认 = 2.0 * 0.01 = 0.02 秒
```

初始化为一个极小值(20ms),让首帧 output 时 `time - latency_` 几乎就是 `time`,而所有 StoredInput 都在 `time` 附近,插值正常。

#### 16.3.3 Waypoint 初始化

```
previousWaypoint_.time_ = time - 2 * 0.01 = time - 0.02
nextWaypoint_.time_     = time - 1 * 0.01 = time - 0.01
```

两个 Waypoint 时间差 0.01s,位置相同。这意味着首帧 output 时插值结果就是"这次 input 的位置",没有抖动。

## 十七、output 方法工作流程

### 17.1 output 完整源码

```cpp
// lib/connection/avatar_filter_helper.cpp:355-414
double AvatarFilterHelper::output( double time, SpaceID & rSpaceID,
        EntityID & rVehicleID, Position3D & rPosition, Vector3 & rVelocity,
        Direction3D & rDirection )
{
    // 1. 如果有新 input,重算 idealLatency
    if (gotNewInput_)
    {
        gotNewInput_ = false;

        const int maxLatencyFrame = std::min( inputCount_, (uint)NUM_STORED_INPUTS ) - 1;

        if (maxLatencyFrame > 0)
        {
            const double newestTime = this->getStoredInput( 0 ).time_;
            const double olderTime = this->getStoredInput( maxLatencyFrame ).time_;

            float latencyFrames = AvatarFilterSettings::s_latencyFrames_;
            latencyFrames =
                Math::clamp( 0.0f, latencyFrames, float( maxLatencyFrame ) );

            double ratio = (maxLatencyFrame - latencyFrames) / (double)maxLatencyFrame;

            idealLatency_ = float( time - Math::lerp( ratio, olderTime, newestTime ) );
        }

        // idealLatency 不能小于 s_latencyMinimum_(默认 100ms)
        idealLatency_ = std::max( idealLatency_, AvatarFilterSettings::s_latencyMinimum_ );
    }

    // 2. latency_ 朝 idealLatency_ 平滑移动
    float dTime = float(time - timeOfLastOutput_);
    float dLatency = (AvatarFilterSettings::s_latencyVelocity_ * dTime) *
        std::min( 1.0f,
            powf( fabsf( idealLatency_ - latency_ ),
                AvatarFilterSettings::s_latencyCurvePower_ ) );

    if (idealLatency_ > latency_)
    {
        latency_ += dLatency;
        latency_ = std::min( latency_, idealLatency_ );
    }
    else
    {
        latency_ -= dLatency;
        latency_ = std::max( latency_, idealLatency_ );
    }

    // 3. 记录这次的 output time
    timeOfLastOutput_ = time;

    // 4. 计算实际查询时间
    double outputTime = time - latency_;

    // 5. 提取插值结果
    this->extract( outputTime, rSpaceID, rVehicleID, rPosition, rVelocity,
        rDirection );

    return outputTime;
}
```

### 17.2 步骤详解

#### 17.2.1 步骤 1:重算 idealLatency

```cpp
const int maxLatencyFrame = std::min( inputCount_, (uint)NUM_STORED_INPUTS ) - 1;
```

`maxLatencyFrame` 表示"用最近几个 input 估算包间隔"。

- 如果 `inputCount_ >= 8`,用 8-1=7;
- 如果 `inputCount_ = 3`,用 3-1=2;
- 如果 `inputCount_ = 1`(只有一个 input),maxLatencyFrame = 0,跳过计算。

```cpp
const double newestTime = this->getStoredInput( 0 ).time_;
const double olderTime = this->getStoredInput( maxLatencyFrame ).time_;
```

`newestTime` 是最新 input 的 time,`olderTime` 是 `maxLatencyFrame` 个之前的 time。两者之差就是"过去 N 个 input 的总时间跨度"。

```cpp
float latencyFrames = AvatarFilterSettings::s_latencyFrames_;  // 默认 2.0
latencyFrames = Math::clamp( 0.0f, latencyFrames, float( maxLatencyFrame ) );
```

`latencyFrames` 表示"理想延迟应该等于几个 input 周期"。默认 2.0(2 个 input 周期)。

```cpp
double ratio = (maxLatencyFrame - latencyFrames) / (double)maxLatencyFrame;
```

`ratio` 是"插值参数"。例如 maxLatencyFrame=7, latencyFrames=2:
- `ratio = (7-2)/7 = 0.714`

```cpp
idealLatency_ = float( time - Math::lerp( ratio, olderTime, newestTime ) );
```

`Math::lerp(ratio, olderTime, newestTime)` 返回 `olderTime + ratio * (newestTime - olderTime)`。

举例:
- `time = 100.0`(当前 gameTime)
- `newestTime = 99.5`(最新 input 时间)
- `olderTime = 92.0`(7 个 input 之前的时间)
- `ratio = 0.714`
- `lerp = 92.0 + 0.714 * (99.5 - 92.0) = 92.0 + 5.355 = 97.355`
- `idealLatency_ = 100.0 - 97.355 = 2.645 秒`

**含义**:从历史看,过去 7 个 input 跨越了 7.5 秒(平均 1.07 秒/包)。我们想延迟 2 个包周期 ≈ 2.14 秒。`ratio = 0.714` 表示"从 older 走到 newer 的 71.4% 处"对应 2 个包的延迟。最终 `idealLatency = gameTime - lerp` = 2.645 秒。

```cpp
idealLatency_ = std::max( idealLatency_, AvatarFilterSettings::s_latencyMinimum_ );
```

兜底:`idealLatency_` 不能小于 100ms(默认),即使包来得很快。

#### 17.2.2 步骤 2:latency_ 平滑移动

```cpp
float dTime = float(time - timeOfLastOutput_);
float dLatency = (AvatarFilterSettings::s_latencyVelocity_ * dTime) *
    std::min( 1.0f,
        powf( fabsf( idealLatency_ - latency_ ),
            AvatarFilterSettings::s_latencyCurvePower_ ) );
```

`dLatency` 是这次允许 latency_ 移动的量。

- `(s_latencyVelocity_ * dTime)` 是基础量(默认 1.0 * dTime);
- `powf(|idealLatency - latency|, 2.0)` 是缩放因子,差距越大缩放越大;
- `std::min(1.0, ...)` 限制单次最多移动 1.0 倍基础量。

**含义**:差距大时移动快(`|diff|^2` 在差距 1.0 时是 1.0),差距小时移动慢(`|diff|^2` 在差距 0.1 时是 0.01)。这是"指数衰减"式的趋近,既快又稳。

```cpp
if (idealLatency_ > latency_)
{
    latency_ += dLatency;
    latency_ = std::min( latency_, idealLatency_ );
}
else
{
    latency_ -= dLatency;
    latency_ = std::max( latency_, idealLatency_ );
}
```

根据方向选择加或减,且不超过 idealLatency_。

#### 17.2.3 步骤 3-5

```cpp
timeOfLastOutput_ = time;
double outputTime = time - latency_;
this->extract( outputTime, rSpaceID, rVehicleID, rPosition, rVelocity,
    rDirection );
return outputTime;
```

记录这次 output 的 time,计算实际查询时间 `outputTime = time - latency_`,调用 `extract` 做实际插值。

### 17.3 latency_ 移动的可视化

```
   latency_                              idealLatency_
       │                                       │
       ▼                                       ▼
time──┬───────────────────────────────────────┬──→
      │                                       │
      └──outputTime = time - latency_          │
                                                │
                              (latency 朝 ideal 移动)
```

随着 input 持续到达:
- 包间隔稳定 → idealLatency 稳定 → latency 平滑趋近;
- 包间隔突然变大(网络变差)→ idealLatency 增大 → latency 缓慢追赶;
- 包间隔突然变小(网络变好)→ idealLatency 减小 → latency 缓慢回落。

**为什么不让 latency 立刻等于 idealLatency?** 因为那样会导致 `outputTime` 跳变,实体位置会突然回退或前进,造成视觉抖动。缓慢趋近是必要的。

## 十八、extract 插值算法详解

### 18.1 extract 完整源码

```cpp
// lib/connection/avatar_filter_helper.cpp:507-556
void AvatarFilterHelper::extract( double time, SpaceID & outputSpaceID,
        EntityID & outputVehicleID, Position3D & outputPosition,
        Vector3 & outputVelocity, Direction3D & outputDirection )
{
    BW_GUARD;

    // 1. AvatarFilter 失效时,直接返回最新 input
    if (!AvatarFilterHelper::isActive())
    {
        const StoredInput & mostRecentInput = this->getStoredInput( 0 );

        outputSpaceID = mostRecentInput.spaceID_;
        outputVehicleID = mostRecentInput.vehicleID_;
        outputPosition = mostRecentInput.position_;
        outputDirection = mostRecentInput.direction_;
        outputVelocity.setZero();

        return;
    }

    // 2. 如果请求时间超出当前 Waypoint 范围,选新 Waypoint
    if (time > nextWaypoint_.time_)
    {
        this->chooseNextWaypoint( time );
    }

    // 3. 计算插值参数
    float proportionateDifferenceInTime =
        float((time - previousWaypoint_.time_ ) /
            (nextWaypoint_.time_ - previousWaypoint_.time_));

    // 4. 输出坐标系 = nextWaypoint 的坐标系
    outputSpaceID = nextWaypoint_.spaceID_;
    outputVehicleID = nextWaypoint_.vehicleID_;

    // 5. 位置线性插值
    outputPosition.lerp( previousWaypoint_.position_, nextWaypoint_.position_,
        proportionateDifferenceInTime );

    // 6. 速度 = 位移 / 时间差
    outputVelocity = (nextWaypoint_.position_ - previousWaypoint_.position_) /
        float( nextWaypoint_.time_- previousWaypoint_.time_);

    // 7. 朝向线性插值(用 Angle::lerp 处理 -π~π 边界)
    Angle yaw;
    yaw.lerp( previousWaypoint_.direction_.yaw,
        nextWaypoint_.direction_.yaw,
        proportionateDifferenceInTime );

    Angle pitch;
    pitch.lerp( previousWaypoint_.direction_.pitch,
        nextWaypoint_.direction_.pitch,
        proportionateDifferenceInTime );

    outputDirection.yaw = yaw;
    outputDirection.pitch = pitch;
    outputDirection.roll = 0.f;     // roll 始终置 0
}
```

### 18.2 算法步骤

#### 18.2.1 步骤 1:isActive 检查

```cpp
if (!AvatarFilterHelper::isActive())
{
    // 退化为 DumbFilter 行为
    return;
}
```

`AvatarFilterSettings::s_isActive_` 是个全局开关,可通过 watcher 调整。设为 false 时,所有 AvatarFilter 退化为"返回最新 input",用于调试对比(`fantasydemo` 中按 `DEBUG-H` 切换)。

#### 18.2.2 步骤 2:Waypoint 更新

```cpp
if (time > nextWaypoint_.time_)
{
    this->chooseNextWaypoint( time );
}
```

如果请求的 `time` 超过当前 `nextWaypoint_.time_`,说明需要进入下一段。详见 §19。

#### 18.2.3 步骤 3:插值参数

```cpp
float proportionateDifferenceInTime =
    float((time - previousWaypoint_.time_ ) /
        (nextWaypoint_.time_ - previousWaypoint_.time_));
```

`alpha = (time - prev.time) / (next.time - prev.time)`

注意 `alpha` 可能 > 1(超出 nextWaypoint.time),此时会做**外推**——位置在 nextWaypoint 之外。但这通常只发生在 `chooseNextWaypoint` 没有可用 input 时(所有历史都比 time 旧)。

#### 18.2.4 步骤 4-5:位置插值

```cpp
outputPosition.lerp( previousWaypoint_.position_, nextWaypoint_.position_,
    proportionateDifferenceInTime );
```

`Position3D::lerp(a, b, t) = a + (b - a) * t`,标准的线性插值。

#### 18.2.5 步骤 6:速度估计

```cpp
outputVelocity = (nextWaypoint_.position_ - previousWaypoint_.position_) /
    float( nextWaypoint_.time_ - previousWaypoint_.time_);
```

**速度 = 单位时间位移**。这个速度供动画系统决定走/跑动画。

#### 18.2.6 步骤 7:朝向插值

```cpp
Angle yaw;
yaw.lerp( previousWaypoint_.direction_.yaw,
    nextWaypoint_.direction_.yaw,
    proportionateDifferenceInTime );
```

`Angle::lerp` 不是简单线性插值,它**处理角度的环形边界**:

```cpp
// lib/math/angle.ipp:264-267
inline void Angle::lerp( Angle a, Angle b, float alpha )
{
    *this = ( sameSignAngle( a, b ) - a) * alpha + a;
}
```

`sameSignAngle` 保证 `b` 与 `a` 在同一个 2π 周期内,避免插值绕远路:

```cpp
// lib/math/angle.ipp:198-212
inline float Angle::sameSignAngle( float angle, float closest )
{
    if ( closest > angle + MATH_PI )
    {
        return closest - 2.0f * MATH_PI;    // b 太大,减 2π
    }
    else if ( closest < angle - MATH_PI )
    {
        return closest + 2.0f * MATH_PI;   // b 太小,加 2π
    }
    else
    {
        return closest;                      // 已经同周期
    }
}
```

**示例**:
- a = 175°,b = -175°
- 直接线性插值:lerp = 175 + (-175 - 175) * 0.5 = 0°(绕远路,从 175° 退到 0°)
- 用 sameSignAngle:b → 185°(=-175° + 360°)
- lerp = 175 + (185 - 175) * 0.5 = 180°(走最短路径,从 175° 走到 180°)

#### 18.2.7 roll 始终 0

```cpp
outputDirection.roll = 0.f;
```

`AvatarFilterHelper` 不插值 roll——注释说"目前 AvatarFilter 忽略 roll,这里也保持一致"。Roll 通常由动画系统(如倾斜的鸟)或 `AvatarDropFilter`(对齐地面法线)处理。

### 18.3 关于 Catmull-Rom 的说明

任务指引中提到"Catmull-Rom 样条插值"。需要明确:**BigWorld 14.4.1 的 AvatarFilter 实际上没有使用 Catmull-Rom 样条**,而是使用**线性插值(lerp)**。

`AvatarFilterHelper::extract` 中:

```cpp
outputPosition.lerp( previousWaypoint_.position_, nextWaypoint_.position_,
    proportionateDifferenceInTime );
```

这是单纯的线性插值。但 BigWorld 通过以下机制达到了类似样条的效果:

1. **误差盒钳制**:Waypoint 在 chooseNextWaypoint 中被钳制到误差盒内,避免线性段过于偏离真实轨迹;
2. **多输入平滑**:8 个历史输入提供了多个采样点,线性段之间的"拐角"被新 input 不断修正;
3. **坐标系变换**:跨坐标系时的精确变换避免了"假弯曲"。

虽然在源码中搜索 `CatmullRom` 不会找到 Filter 相关的实现,但 BigWorld 的设计哲学——**通过多采样点 + 误差盒钳制实现近似平滑**——在视觉效果上接近 Catmull-Rom 的"经过控制点"特性。如果读者期望真正的样条插值,可以通过继承 `AvatarFilter` 并重写 `output` 来实现(详见 §36.4 扩展建议)。

### 18.4 退化模式(DumbFilter 等价)

```cpp
if (!AvatarFilterHelper::isActive())
{
    const StoredInput & mostRecentInput = this->getStoredInput( 0 );
    outputSpaceID = mostRecentInput.spaceID_;
    outputVehicleID = mostRecentInput.vehicleID_;
    outputPosition = mostRecentInput.position_;
    outputDirection = mostRecentInput.direction_;
    outputVelocity.setZero();
    return;
}
```

设置 `AvatarFilterSettings::s_isActive_ = false` 后,所有 AvatarFilter 退化为返回最新 input,且**速度为 0**(因为没有插值)。

这是用于演示和调试的开关,生产环境不会关闭。

## 十九、chooseNextWaypoint 算法深度剖析

`chooseNextWaypoint` 是 AvatarFilter 最复杂的算法,负责从历史 StoredInput 中选出下一对插值端点。

### 19.1 算法概述

源码注释(`avatar_filter_helper.cpp:559-585`)描述了三种情况:

1. **Two inputs ahead of time**:有两个比 time 更新的 input,用 look-ahead 构造新 Waypoint,并钳制到误差盒;
2. **Only one input ahead of time**:只有一个比 time 更新的 input,外推当前位置到该 input 时间;
3. **No inputs ahead of time**:没有 input 比 time 更新,保持原位等待。

### 19.2 完整源码

```cpp
// lib/connection/avatar_filter_helper.cpp:586-733
void AvatarFilterHelper::chooseNextWaypoint( double time )
{
    BW_GUARD;

    Waypoint & previousWaypoint = previousWaypoint_;
    Waypoint & currentWaypoint = nextWaypoint_;
    Waypoint newWaypoint;

    // 情况 3:没有 input 比 time 新,原地等待
    if (this->getStoredInput( 0 ).time_ < time)
    {
        // 没有更多数据,原地站一帧
        previousWaypoint_ = nextWaypoint_;
        nextWaypoint_.time_ = time;
        return;
    }

    // 找到第一个比 time 更新的 input 索引
    int nextInputIndex = (NUM_STORED_INPUTS - 1);
    while (nextInputIndex > 0)
    {
        if (this->getStoredInput( nextInputIndex ).time_ > time)
        {
            break;
        }
        --nextInputIndex;
    }

    const StoredInput & lookAheadInput = this->getStoredInput( 0 );
    const StoredInput & nextInput = this->getStoredInput( nextInputIndex );

    // 构造新 Waypoint(基于 nextInput)
    newWaypoint.time_ = nextInput.time_;
    newWaypoint.spaceID_ = nextInput.spaceID_;
    newWaypoint.vehicleID_ = nextInput.vehicleID_;
    newWaypoint.direction_ = nextInput.direction_;
    newWaypoint.storedInput_ = nextInput;

    // 把 prev/current Waypoint 变换到新坐标系(nextInput 的坐标系)
    previousWaypoint.changeCoordinateSystem( this->environment(),
        newWaypoint.spaceID_, newWaypoint.vehicleID_ );
    currentWaypoint.changeCoordinateSystem( this->environment(),
        newWaypoint.spaceID_, newWaypoint.vehicleID_ );

    // 计算 lookAhead 位置(在 prev→current 段上的投影)
    float lookAheadRelativeDifferenceInTime =
        float((lookAheadInput.time_ - previousWaypoint.time_) /
            (currentWaypoint.time_ - previousWaypoint.time_) );

    Position3D lookAheadPosition;
    lookAheadPosition.lerp( previousWaypoint.position_,
                            currentWaypoint.position_,
                            lookAheadRelativeDifferenceInTime );

    Direction3D unusedDirection( Vector3::zero() );

    // 把 lookAheadPosition 转到世界坐标
    this->transformIntoCommon( newWaypoint.spaceID_,
        newWaypoint.vehicleID_, lookAheadPosition, unusedDirection );

    // 转到 lookAheadInput 的坐标系,做误差盒钳制
    this->transformFromCommon( lookAheadInput.spaceID_,
        lookAheadInput.vehicleID_, lookAheadPosition, unusedDirection );

    lookAheadPosition.clamp(
        lookAheadInput.position_ - lookAheadInput.positionError_,
        lookAheadInput.position_ + lookAheadInput.positionError_ );

    // 转回 newWaypoint 的坐标系
    this->transformIntoCommon( lookAheadInput.spaceID_,
        lookAheadInput.vehicleID_, lookAheadPosition, unusedDirection );
    this->transformFromCommon( newWaypoint.spaceID_,
        newWaypoint.vehicleID_, lookAheadPosition, unusedDirection );

    // 处理重叠误差盒:如果新旧误差盒重叠,保持当前位置
    BoundingBox newWaypointBB(
        newWaypoint.storedInput_.position_ -
            newWaypoint.storedInput_.positionError_,
        newWaypoint.storedInput_.position_ +
            newWaypoint.storedInput_.positionError_);

    BoundingBox currentWaypointBB(
        currentWaypoint.storedInput_.position_ -
            currentWaypoint.storedInput_.positionError_,
        currentWaypoint.storedInput_.position_ +
            currentWaypoint.storedInput_.positionError_ );

    if ((newWaypoint.spaceID_ ==
                currentWaypoint.storedInput_.spaceID_) &&
            (newWaypoint.vehicleID_ ==
                currentWaypoint.storedInput_.vehicleID_) &&
            !almostEqual( newWaypoint.storedInput_.positionError_,
                currentWaypoint.storedInput_.positionError_) &&
            newWaypointBB.intersects( currentWaypointBB ))
    {
        // 误差盒重叠,保持静止(只调整误差盒)
        newWaypoint.position_ = currentWaypoint.position_;
    }
    else
    {
        // 正常情况:在 current→lookAhead 之间插值
        float proportionateDifferenceInTime =
            float( (nextInput.time_ - currentWaypoint.time_) /
                (lookAheadInput.time_ - currentWaypoint.time_) );

        newWaypoint.position_.lerp( currentWaypoint.position_,
            lookAheadPosition,
            proportionateDifferenceInTime );
    }

    // 钳制 newWaypoint.position_ 到 nextInput 的误差盒内
    BoundingBox nextInputBB(
        nextInput.position_ - nextInput.positionError_,
        nextInput.position_ + nextInput.positionError_ );

    if (!nextInputBB.intersects(newWaypoint.position_))
    {
        Position3D clampedPosition( newWaypoint.position_ );

        clampedPosition.clamp(
            nextInput.position_ - nextInput.positionError_,
            nextInput.position_ + nextInput.positionError_ );

        Vector3 lookAheadVector = newWaypoint.position_ -
            currentWaypoint.position_;

        Vector3 clampedVector = clampedPosition - currentWaypoint.position_;

        if (lookAheadVector.lengthSquared() > 0.0f)
        {
            // 把 clamped 投影到 lookAhead 方向上
            newWaypoint.position_ = currentWaypoint.position_ +
                clampedVector.projectOnto( lookAheadVector );
        }
        else
        {
            newWaypoint.position_ = currentWaypoint.position_;
        }

        newWaypoint.position_.clamp(
            nextInput.position_ - nextInput.positionError_,
            nextInput.position_ + nextInput.positionError_ );
    }

    previousWaypoint_ = currentWaypoint;
    nextWaypoint_ = newWaypoint;
}
```

### 19.3 算法步骤详解

#### 19.3.1 步骤 A:无 input 处理

```cpp
if (this->getStoredInput( 0 ).time_ < time)
{
    previousWaypoint_ = nextWaypoint_;
    nextWaypoint_.time_ = time;
    return;
}
```

如果最新 StoredInput(索引 0)的 time_ 比 requested time 还旧(即所有历史都过期了),保持位置不变,只把 `nextWaypoint_.time_` 设为 time(让 alpha=0,静止)。

这发生在两种场景:
1. **网络中断**:长时间没有新 input;
2. **远端实体**:更新频率极低,Latency 不够大。

#### 19.3.2 步骤 B:找 nextInputIndex

```cpp
int nextInputIndex = (NUM_STORED_INPUTS - 1);
while (nextInputIndex > 0)
{
    if (this->getStoredInput( nextInputIndex ).time_ > time)
    {
        break;
    }
    --nextInputIndex;
}
```

从最旧的 StoredInput 开始向前找,找到第一个 `time_ > time` 的索引。这意味着:

- `nextInputIndex` 是"第一个比 requested time 新的 StoredInput";
- `nextInputIndex - 1` 是"最后一个比 requested time 旧的 StoredInput";

如果所有 StoredInput 都比 time 新(可能 time 太小),`nextInputIndex = 0`。

#### 19.3.3 步骤 C:构造 newWaypoint 框架

```cpp
newWaypoint.time_ = nextInput.time_;
newWaypoint.spaceID_ = nextInput.spaceID_;
newWaypoint.vehicleID_ = nextInput.vehicleID_;
newWaypoint.direction_ = nextInput.direction_;
newWaypoint.storedInput_ = nextInput;
```

注意:`newWaypoint.position_` 还没设置,后面计算。

#### 19.3.4 步骤 D:坐标系变换

```cpp
previousWaypoint.changeCoordinateSystem( this->environment(),
    newWaypoint.spaceID_, newWaypoint.vehicleID_ );
currentWaypoint.changeCoordinateSystem( this->environment(),
    newWaypoint.spaceID_, newWaypoint.vehicleID_ );
```

把 `previousWaypoint` 和 `currentWaypoint` 都变换到 newWaypoint 的坐标系。这样后续所有的位置运算都在同一个坐标系里。

#### 19.3.5 步骤 E:lookAhead 位置计算

```cpp
const StoredInput & lookAheadInput = this->getStoredInput( 0 );   // 最新 input

float lookAheadRelativeDifferenceInTime =
    float((lookAheadInput.time_ - previousWaypoint.time_) /
        (currentWaypoint.time_ - previousWaypoint.time_) );

Position3D lookAheadPosition;
lookAheadPosition.lerp( previousWaypoint.position_,
                        currentWaypoint.position_,
                        lookAheadRelativeDifferenceInTime );
```

`lookAheadInput` 是最新的 StoredInput(索引 0),它代表"实体未来的方向"。`lookAheadPosition` 是在 `previousWaypoint → currentWaypoint` 段上,以 `lookAheadInput.time_` 为参数的插值点。

直观含义:**如果让实体从 prev 一路走到 current,那么在 lookAheadInput.time_ 这个时刻,它应该在 lookAheadPosition**。

#### 19.3.6 步骤 F:lookAhead 误差盒钳制

```cpp
// 转到 lookAheadInput 坐标系
this->transformIntoCommon( newWaypoint.spaceID_, ..., lookAheadPosition, ... );
this->transformFromCommon( lookAheadInput.spaceID_, ..., lookAheadPosition, ... );

// 钳制到 lookAheadInput 的误差盒
lookAheadPosition.clamp(
    lookAheadInput.position_ - lookAheadInput.positionError_,
    lookAheadInput.position_ + lookAheadInput.positionError_ );

// 转回 newWaypoint 坐标系
this->transformIntoCommon( lookAheadInput.spaceID_, ..., lookAheadPosition, ... );
this->transformFromCommon( newWaypoint.spaceID_, ..., lookAheadPosition, ... );
```

把 `lookAheadPosition` 钳制到 `lookAheadInput` 的误差盒内。这样保证了:**任何插值结果都不会偏离最新 input 的误差盒**,避免视觉跳变。

#### 19.3.7 步骤 G:重叠误差盒检测

```cpp
BoundingBox newWaypointBB( ... );   // nextInput 的误差盒
BoundingBox currentWaypointBB( ... );  // currentWaypoint 的存储 input 误差盒

if ((newWaypoint.spaceID_ == currentWaypoint.storedInput_.spaceID_) &&
        (newWaypoint.vehicleID_ == currentWaypoint.storedInput_.vehicleID_) &&
        !almostEqual( newWaypoint.storedInput_.positionError_,
            currentWaypoint.storedInput_.positionError_) &&
        newWaypointBB.intersects( currentWaypointBB ))
{
    // 误差盒重叠 → 保持静止
    newWaypoint.position_ = currentWaypoint.position_;
}
else
{
    // 否则,在 current→lookAhead 之间插值
    float proportionateDifferenceInTime =
        float( (nextInput.time_ - currentWaypoint.time_) /
            (lookAheadInput.time_ - currentWaypoint.time_) );

    newWaypoint.position_.lerp( currentWaypoint.position_,
        lookAheadPosition,
        proportionateDifferenceInTime );
}
```

**重叠误差盒场景**:服务器精度提高(误差盒变小),但新旧误差盒重叠,且实体已经在重叠区域内。此时不移动,避免无意义的微动。

**正常场景**:在 `currentWaypoint` 和 `lookAheadPosition` 之间按时间比例插值。

#### 19.3.8 步骤 H:nextInput 误差盒钳制

```cpp
BoundingBox nextInputBB( nextInput.position_ - nextInput.positionError_,
                         nextInput.position_ + nextInput.positionError_ );

if (!nextInputBB.intersects(newWaypoint.position_))
{
    Position3D clampedPosition( newWaypoint.position_ );
    clampedPosition.clamp( nextInput.position_ - nextInput.positionError_,
                           nextInput.position_ + nextInput.positionError_ );

    Vector3 lookAheadVector = newWaypoint.position_ - currentWaypoint.position_;
    Vector3 clampedVector = clampedPosition - currentWaypoint.position_;

    if (lookAheadVector.lengthSquared() > 0.0f)
    {
        // 把 clamped 投影到 lookAhead 方向
        newWaypoint.position_ = currentWaypoint.position_ +
            clampedVector.projectOnto( lookAheadVector );
    }
    else
    {
        newWaypoint.position_ = currentWaypoint.position_;
    }

    newWaypoint.position_.clamp(
        nextInput.position_ - nextInput.positionError_,
        nextInput.position_ + nextInput.positionError_ );
}
```

**含义**:`newWaypoint.position_` 是基于 lookAhead 计算的,可能不在 `nextInput` 的误差盒内。此时:

1. 先把它 clamp 到 nextInput 误差盒,得到 `clampedPosition`;
2. 计算 `clampedPosition - currentWaypoint`(向量);
3. 把这个向量投影到 `lookAheadVector` 方向上,保持"前进方向"但限制长度;
4. 再 clamp 一次(投影可能超出)。

**为什么要投影?** 直接 clamp 可能导致"垂直于前进方向"的偏移,看起来不自然。投影到前进方向上,实体仍沿着原方向走,只是被限制在误差盒内。

#### 19.3.9 步骤 I:更新 Waypoint

```cpp
previousWaypoint_ = currentWaypoint;
nextWaypoint_ = newWaypoint;
```

老的 `nextWaypoint_` 变成新的 `previousWaypoint_`,新计算的 `newWaypoint` 成为 `nextWaypoint_`。

### 19.4 算法可视化

```
历史 StoredInput (时间从新到旧,索引 0~7):

   I0(最新)  I1    I2    I3    I4    I5    I6    I7(最旧)
    ●─────●─────●─────●─────●─────●─────●─────●
                                          ↑
                                  requested time = time - latency

prev Waypoint      current Waypoint       newWaypoint(待计算)
     ●─────────────────●───────────────────● (待)
                                    ↑
                              nextInput (第一个比 time 新的 StoredInput)

lookAheadPosition:
  在 prev→current 段上,以 lookAheadInput.time_ 为参数的插值点
  钳制到 lookAheadInput 误差盒内

newWaypoint.position_:
  在 current→lookAheadPosition 之间按时间比例插值
  钳制到 nextInput 误差盒内
```

## 二十、延迟(latency)自适应机制

### 20.1 延迟的概念

```
    gameTime(现在)                    最新 StoredInput 的 time_
        │                                       │
        ▼                                       ▼
time──┬─────────────────────────────────────────┬──→
      │                                         │
      │←── latency_ ──→│                        │
      │                 │                        │
      ▼                 ▼                        │
   outputTime = time - latency_                  │
                                                │
                          实际查询历史的时刻
```

- **`latency_`**:Filter 当前使用的延迟,Filter 输出位置对应的时刻 = `gameTime - latency_`。
- **`idealLatency_`**:基于最近 input 间隔估算的理想延迟。
- **`s_latencyMinimum_`**:最小延迟下限(默认 100ms),防止 latency 过小导致"撞墙"(没有历史可插值)。
- **`s_latencyFrames_`**:理想延迟以"input 周期数"计(默认 2.0)。

### 20.2 idealLatency_ 计算公式

```
maxLatencyFrame = min(inputCount, NUM_STORED_INPUTS) - 1

newestTime = storedInputs_[0].time_
olderTime  = storedInputs_[maxLatencyFrame].time_

ratio = (maxLatencyFrame - latencyFrames) / maxLatencyFrame

lerp = olderTime + ratio * (newestTime - olderTime)

idealLatency_ = max(gameTime - lerp, s_latencyMinimum_)
```

#### 20.2.1 公式推导

假设最近 N+1 个 input 的时间是 `t_0, t_1, ..., t_N`(N=maxLatencyFrame),其中 `t_0` 最新,`t_N` 最旧。

平均包间隔 = `(t_0 - t_N) / N`

理想延迟 = `latencyFrames` 个包间隔 = `latencyFrames * (t_0 - t_N) / N`

我们想找到时间点 `T`,使得 `gameTime - T = idealLatency`,即:
```
T = gameTime - latencyFrames * (t_0 - t_N) / N
  = gameTime - latencyFrames * (t_0 - t_N) / maxLatencyFrame
```

源码用 lerp 表达:
```
ratio = (maxLatencyFrame - latencyFrames) / maxLatencyFrame
lerp = olderTime + ratio * (newestTime - olderTime)
     = t_N + ratio * (t_0 - t_N)
     = t_N + (maxLatencyFrame - latencyFrames)/maxLatencyFrame * (t_0 - t_N)
     = t_N + (t_0 - t_N) - latencyFrames * (t_0 - t_N) / maxLatencyFrame
     = t_0 - latencyFrames * (t_0 - t_N) / maxLatencyFrame
```

所以:
```
idealLatency_ = gameTime - lerp
             = gameTime - t_0 + latencyFrames * (t_0 - t_N) / maxLatencyFrame
             = (gameTime - t_0) + latencyFrames * avgInterval
```

其中 `gameTime - t_0` 是"现在距最新 input 多久",`latencyFrames * avgInterval` 是"理想延迟 = N 个平均周期"。

#### 20.2.2 示例

假设:
- `gameTime = 100.0`
- 最新 input 时间 `t_0 = 99.5`(0.5s 前到的)
- 8 个 input 前的时间 `t_7 = 92.0`(过去 7.5s 收到 8 个包)
- `latencyFrames = 2.0`

则:
```
maxLatencyFrame = 7
ratio = (7 - 2)/7 ≈ 0.714
lerp = 92.0 + 0.714 * (99.5 - 92.0) = 92.0 + 5.355 = 97.355
idealLatency_ = 100.0 - 97.355 = 2.645 秒
```

含义:当前网络平均 1.07s/包,我们想延迟 2 个包周期 ≈ 2.14s,加上"距最新 input 0.5s",总延迟 2.645s。

### 20.3 latency_ 平滑移动公式

```
dTime = gameTime - timeOfLastOutput_
dLatency = s_latencyVelocity_ * dTime * min(1.0, |idealLatency - latency_|^s_latencyCurvePower_)

if (idealLatency > latency_):
    latency_ += dLatency
    latency_ = min(latency_, idealLatency_)
else:
    latency_ -= dLatency
    latency_ = max(latency_, idealLatency_)
```

#### 20.3.1 公式特性

- `s_latencyVelocity_ * dTime`:基础变化量(默认 1.0 * dTime);
- `|diff|^2`:差距大时缩放变大;
- `min(1.0, ...)`:单次最多移动基础量。

**效果**:差距大时快追,差距小时慢追,平滑趋近。

#### 20.3.2 示例

- 当前 `latency_ = 0.5`
- `idealLatency_ = 2.0`
- `dTime = 0.016`(60fps)
- `s_latencyVelocity_ = 1.0`,`s_latencyCurvePower_ = 2.0`

```
diff = 1.5
dLatency = 1.0 * 0.016 * min(1.0, 1.5^2) = 0.016 * 1.0 = 0.016
newLatency = 0.5 + 0.016 = 0.516
```

60 帧后(1 秒):
```
每帧 +0.016,共 60 帧 → +0.96
newLatency ≈ 0.5 + 0.96 = 1.46
```

但实际不是线性累加,因为每帧 diff 都在变小:
- 第 1 帧:diff=1.5,dLatency=0.016
- 第 30 帧:diff≈1.0,dLatency=0.016*1.0=0.016(还是最大)
- 第 50 帧:diff≈0.5,dLatency=0.016*0.25=0.004(变慢)
- 第 60 帧:diff≈0.04,dLatency=0.016*0.0016=0.000026(很慢)

这是典型的"先快后慢"指数衰减,大约 1.5 秒内追到 idealLatency。

### 20.4 latency 自适应的意义

| 场景 | idealLatency | latency_ 行为 |
|------|--------------|---------------|
| 网络稳定,10Hz 更新 | ~0.2s | 稳定在 0.2s |
| 网络抖动,部分包延迟 | 增大 | 缓慢增大,避免抖动 |
| 网络中断,无新 input | 保持上次值 | 保持上次值,实体静止 |
| 网络恢复,突发多包 | 减小 | 缓慢减小,避免位置回退 |
| 远端实体,稀疏更新 | 增大 | 大幅滞后,优先稳定 |

### 20.5 latency 与视觉延迟的关系

`latency_` 越大,实体视觉位置越"滞后"于服务器真实位置。这是一个 trade-off:

- **latency 大**:平滑度好,但响应感差(玩家点击 → 实体反应慢);
- **latency 小**:响应感好,但容易抖动(没有足够历史可插值)。

BigWorld 的默认配置(`s_latencyFrames_ = 2.0`)选择"延迟 2 个包周期",在 10Hz 更新下约 200ms,这是 MMOG 的可接受范围。

### 20.6 latency_ 的边界保护

```cpp
// lib/connection/avatar_filter_helper.cpp:381
idealLatency_ = std::max( idealLatency_, AvatarFilterSettings::s_latencyMinimum_ );
```

`s_latencyMinimum_ = 0.10f`(100ms)是硬下限。即使包来得非常快(比如本地服务器 100Hz),idealLatency 也不会低于 100ms。

**为什么需要这个下限?**

- 防止 `latency_ = 0` 时,`outputTime = gameTime`,而最新 StoredInput 的 time_ 总是略早于 gameTime(网络传输延迟),导致 `chooseNextWaypoint` 走"无 input 可用"分支,实体静止;
- 100ms 是经验值,刚好覆盖一帧的渲染延迟 + 网络抖动。

## 二十一、AvatarFilterCallback 时间回调机制

### 21.1 回调机制概述

`AvatarFilterCallback` 提供"在 Filter 历史时间线到达某时刻时触发回调"的能力。这是 AvatarFilter 独有的特色,用于:

- **脚步声对齐**:角色脚落地时播放脚步声;
- **特效触发**:角色到达某位置时播放技能特效;
- **动画事件**:动画关键帧触发时通知脚本;
- **时序敏感事件**:确保事件在"视觉上正确的时间"发生,而非服务器时间。

### 21.2 AvatarFilterCallback 类

```cpp
// client/avatar_filter_callback.hpp:20-53
class AvatarFilterCallback
{
public:
    AvatarFilterCallback( double targetTime );
    virtual ~AvatarFilterCallback();

    double targetTime() const { return targetTime_; }

    void insertIntoList( ListNode * pListHead );
    bool triggerCallback( double outputTime );
    void removeFromList();

    static AvatarFilterCallback * getFromListNode( ListNode * pListNode )
    {
        return CAST_NODE( pListNode, AvatarFilterCallback, callbackListNode_ );
    }

private:
    virtual bool onCallback( double missedBy ) = 0;

    double targetTime_;
    ListNode callbackListNode_;
};
```

### 21.3 关键方法

#### 21.3.1 insertIntoList 按时间排序插入

```cpp
// client/avatar_filter_callback.cpp:40-63
void AvatarFilterCallback::insertIntoList( ListNode * pListHead )
{
    BW_GUARD;
    // 从后向前找,假设新 callback 通常更新
    ListNode * pPrevNode = pListHead->getPrev();

    while (pPrevNode != pListHead)
    {
        AvatarFilterCallback * pPrevCallback =
            AvatarFilterCallback::getFromListNode( pPrevNode );

        if (pPrevCallback->targetTime() < this->targetTime())
        {
            callbackListNode_.addThisAfter( pPrevNode );
            return;
        }
        pPrevNode = pPrevNode->getPrev();
    }

    // 是最新的元素
    callbackListNode_.addThisAfter( pListHead );
}
```

**算法**:
1. 从链表尾部向前遍历(假设新 callback 时间较新);
2. 找到第一个 `targetTime < this->targetTime` 的节点;
3. 在其后插入;
4. 若遍历到头都没找到,插入到链表头之后(成为最新的)。

这样链表始终按 `targetTime` **升序**排列。

#### 21.3.2 triggerCallback 触发

```cpp
// client/avatar_filter_callback.cpp:70-77
bool AvatarFilterCallback::triggerCallback( double outputTime )
{
    BW_GUARD;
    MF_ASSERT( outputTime >= targetTime_ );
    return this->onCallback( outputTime - targetTime_ );
}
```

`onCallback` 是子类实现的钩子,接收 `missedBy`(错过的时间量)。

### 21.4 PyAvatarFilterCallback 实现

```cpp
// client/py_avatar_filter.cpp:20-88
class PyAvatarFilterCallback : public AvatarFilterCallback
{
public:
    PyAvatarFilterCallback( double targetTime, ScriptObject callbackFn,
        bool shouldPassMissedBy ) :
        AvatarFilterCallback( targetTime ),
        callbackFn_( callbackFn ),
        shouldPassMissedBy_( shouldPassMissedBy )
    {
        BW_GUARD;
        MF_ASSERT( callbackFn_.isCallable() );
    }

    bool onCallback( double missedBy )
    {
        BW_GUARD;
        bool result = false;
        if (!callbackFn_.isCallable())
        {
            return result;
        }

        ScriptArgs callbackArgs;
        if (shouldPassMissedBy_)
        {
            callbackArgs = ScriptArgs::create( float( missedBy ) );
        }
        else
        {
            callbackArgs = ScriptArgs::none();
        }

        ScriptObject callbackResult =
            callbackFn_.callFunction( callbackArgs, ScriptErrorPrint() );

        if (!callbackResult)
        {
            return result;
        }

        if (ScriptInt::check( callbackResult ))
        {
            result = (ScriptInt::create( callbackResult ).asLong() == 1L);
        }
        return result;
    }

    ScriptObject callbackFn_;
    bool shouldPassMissedBy_;
};
```

**关键设计**:
- `callbackFn_` 是 Python 可调用对象;
- `shouldPassMissedBy_` 控制是否传递 `missedBy` 参数;
- 返回值如果是整数 1,则触发"快照"行为(把实体位置回退到 targetTime)。

### 21.5 回调触发流程

```
AvatarFilter::output(time, target):
   │
   │ 1. helper_.output(time, ...) → outputTime
   │ 2. setSpaceVehiclePositionAndDirection(...)
   │
   ▼ 3. 遍历 callback 链表
   │
   │  while (callbackListHead_.getNext() != &callbackListHead_)
   │  {
   │      pFirstCallback = ...
   │      
   │      if (pFirstCallback->targetTime() > outputTime)
   │          break;   // 还没到时间,停止
   │      
   │      if (pFirstCallback->triggerCallback(outputTime))
   │      {
   │          // callback 返回 true → 把实体快照到 targetTime
   │          helper_.extract(pFirstCallback->targetTime(), ...)
   │          setSpaceVehiclePositionAndDirection(...)
   │      }
   │      
   │      pFirstCallback->removeFromList()
   │      delete pFirstCallback
   │  }
   ▼
```

### 21.6 callback 的 whence 参数

Python 接口 `BigWorld.AvatarFilter.callback(whence, fn, extra, shouldPassMissedBy)` 中 `whence` 有三个值:

```cpp
// client/py_avatar_filter.cpp:312-319
switch ( whence )
{
    case -1:    targetTime = pFilter->getStoredInput( 7 ).time_;  break;
    case  0:    targetTime = pFilter->getStoredInput( 0 ).time_;  break;
    case  1:    targetTime = PyFilter::getTimeNow();               break;
    default:    targetTime = 0.0;                                   break;
}
targetTime += extra;
```

| whence | 含义 | targetTime |
|--------|------|------------|
| -1 | 倒数第二输入时间(上一次位置更新开始时) | `storedInputs_[7].time_` |
| 0 | 最后输入时间(当前位置更新开始时) | `storedInputs_[0].time_` |
| 1 | 当前 gameTime(现在) | `getTimeNow()` |

**whence = -1 的语义**:在 AvatarFilter 处理"倒数第二个 StoredInput"那一刻触发。这常用于"上一个位置更新完成,即将开始新位置更新"的时序点。

**whence = 0 的语义**:在 AvatarFilter 处理"最新 StoredInput"时触发。常用于"位置更新到达"事件。

**whence = 1 的语义**:在当前 gameTime 触发(实际是未来 `latency_` 后才会被触发,因为 outputTime = gameTime - latency_ < gameTime)。

### 21.7 callback 的快照行为

如果 callback 返回 1(true),AvatarFilter 会:

```cpp

{
    // 把实体"快照"到 callback 时刻
```

**用途**:精准对齐时序事件,例如脚步声触发时,角色脚正好落在地上。

```cpp
// client/avatar_drop_filter.cpp:54-118
void AvatarDropFilter::onEntityPositionUpdated( Entity & entity )
{
    BW_GUARD;

    // 车辆上的实体不做投影(车辆负责位置)
    if (entity.pVehicle())
    {
        return;
    }

    // 调试用:记录被调试的 filter
    if (g_wpDebugFilter.exists() && g_wpDebugFilter.get() == this->pOwner())
    {
        MF_ASSERT( !entity.isDestroyed() );
        g_wpDebugFilterTarget = entity.pPyEntity().get();
        MF_ASSERT( g_wpDebugFilterTarget.exists() );
    }

    SpaceID spaceID = entity.spaceID();
    Position3D localPos = entity.localPosition();
    Direction3D localDir = entity.localDirection();

    if (spaceID == NULL_SPACE_ID)
    {
        return;
    }

    static DogWatch dwAvatarDropFilter( "AvatarDropFilter" );
    dwAvatarDropFilter.start();

    groundNormal_.set( 0, 1, 0 );

    // 1. 投影到地面,获取落点和法线
    this->filterDropPoint( spaceID, localPos, localPos, &groundNormal_ );
    groundNormal_.normalise();

    // 2. 可选:对齐地面法线(调整 pitch/roll)
    if (alignToGround_)
    {
        Matrix rotation;
        rotation.setIdentity();
        rotation.setRotateY( localDir.yaw );

        // 用四元数构造从 (0,1,0) 到 groundNormal_ 的旋转
        Vector3 slopeAxes( Vector3(0,1,0).crossProduct( groundNormal_ ) );
        Quaternion slopeRotation( slopeAxes,
            1 + Vector3(0,1,0).dotProduct( groundNormal_ ) );
        slopeRotation.normalise();

        Matrix slopeRotationMatrix;
        slopeRotationMatrix.setIdentity();
        slopeRotationMatrix.setRotate( slopeRotation );
        rotation.postMultiply( slopeRotationMatrix );

        localDir.pitch = rotation.pitch();
        localDir.roll = rotation.roll();
    }

    // 3. 重新设置位置(注意保存速度,因为 set 会清速度)
    Vector3 localVelocity = entity.localVelocity();
    entity.setSpaceVehiclePositionAndDirection( spaceID, NULL_ENTITY_ID,
        localPos, localDir );
    entity.localVelocity( localVelocity );

    dwAvatarDropFilter.stop();
}
```

### 22.4 算法步骤

1. **车辆检查**:如果在车上,不做投影(车辆负责);
2. **filterDropPoint**:从当前位置垂直下落,与地形/障碍求交,得到落点和法线;
3. **alignToGround**(可选):用四元数构造"从 (0,1,0) 到 groundNormal_ 的旋转",把这个旋转累加到 yaw 旋转上,得到新的 pitch/roll;
4. **重设位置**:把投影后的位置写回 Entity(注意保存速度)。

### 22.5 四元数对齐地面法线的数学

```cpp
Vector3 slopeAxes( Vector3(0,1,0).crossProduct( groundNormal_ ) );
Quaternion slopeRotation( slopeAxes,
    1 + Vector3(0,1,0).dotProduct( groundNormal_ ) );
```

这是**最短旋转弧**的四元数构造法:

- 旋转轴 = up × normal(叉积给出垂直于二者的轴);
- 旋转角度 = acos(up · normal);
- 四元数 = (axis * sin(θ/2), cos(θ/2));

用 `1 + dot` 是 `cos(θ/2) * 2` 的简化(因为 `cos(θ/2) = sqrt((1 + cos θ) / 2)`):

```
q = (axis * sin(θ/2), cos(θ/2))
  = (axis * sqrt((1 - cos θ) / 2), sqrt((1 + cos θ) / 2))
```

源码用 `axis = up × normal, w = 1 + dot` 的形式,是未归一化的四元数,后续 `normalise()` 修正。

**注释说**:"As the normal and up vectors converge the rotation of the quaternion becomes zero making this cross product safe"——当 normal 接近 up 时,旋转角度趋近 0,叉积虽趋近 0 但四元数也趋近单位四元数,不会出问题。

## 二十三、BoidsFilter 群集过滤器深度剖析

### 23.1 设计意图

`BoidsFilter` 是 `AvatarFilter` 的子类,在 AvatarFilter 平滑插值的基础上,为实体的**辅助模型(auxiliary embodiments)**实现 Boids 群集行为。

适用场景:
- 一群鸟(由一个实体代表,每只鸟是一个辅助模型);
- 一群鱼;
- 蝙蝠群、昆虫群等。

实体本身的移动仍由 AvatarFilter 处理,辅助模型(鸟/鱼)的相对位置由 BoidsFilter 计算。

### 23.2 Boids 算法背景

Boids 是 Craig Reynolds 1987 年提出的群集行为模型,三条规则:

1. **分离(Separation)**:避免与邻居过近;
2. **对齐(Alignment)**:与邻居方向一致;
3. **聚合(Cohesion)**:向邻居中心移动。

BigWorld 的 BoidsFilter 实现了这三条规则,并添加了:
- 全局目标(Goal):向实体当前位置移动;
- 速度阻尼:速度向 normalSpeed 衰减;
- 偏航阻尼:避免急转;
- 俯仰控制:根据高度差调整 pitch;
- 滚转控制:转弯时倾斜;
- 着陆状态:STATE_LANDING 时降落到目标。

### 23.5 output 实现

```cpp
// client/boids_filter.cpp:208-286
void BoidsFilter::output( double time, MovementFilterTarget & target )
{
    BW_GUARD;
    static DogWatch dwBoidsFilterOutput("BoidsFilter");
    dwBoidsFilterOutput.start();

    Entity & entity = static_cast< Entity & >( target );

    // 1. 先调用 AvatarFilter::output(实体本身的位置)
    this->AvatarFilter::output( time, target );

    // 2. 计算 goal(目标位置)
    Vector3 goal( entity.position() );

    if (prevTime_ == -1.f )
    {
        initialHeight_ = goal.y;
    }

    // 3. 飞行状态下,goal.y 抬高到地形上方 20m
    if ( state_ != STATE_LANDING )
    {
        goal.y = Terrain::BaseTerrainBlock::getHeight( goal.x, goal.z ) + 20.f;
        if (goal.y < initialHeight_)
            goal.y = initialHeight_;
    }

    // 4. 计算 dTime
    float dTime = 1.f;
    if ( prevTime_ != -1.f )
    {
        dTime = float(time - prevTime_);
    }
    prevTime_ = time;

    // 5. 同步 boidData_ 数量与辅助模型数量
    EntityEmbodiments & models = entity.auxiliaryEmbodiments();
    int size = static_cast<int>(models.size());
    int oldSize = static_cast<int>(boidData_.size());

    if (oldSize != size)
    {
        boidData_.resize( size );
        for (int i = oldSize; i < size; i++)
        {
            boidData_[i].pos_ += goal;   // 新 boid 从 goal 开始
        }
    }

    // 6. 更新每个 boid
    bool boidsLanded = false;
    for ( int i = 0; i < size; i++ )
    {
        IEntityEmbodimentPtr pCA = models[i];
        boidData_[i].updateModel( goal, &*pCA, *this, dTime,
            timeMultiplier_, state_, radius_ );

        if ( state_ == STATE_LANDING && boidData_[i].pos_ == goal )
        {
            boidsLanded = true;
        }
    }

    // 7. 如果有 boid 着陆,调用脚本回调
    if ( boidsLanded )
    {
        MF_ASSERT( !entity.isDestroyed() );
        entity.pPyEntity().callMethod( "boidsLanded", ScriptErrorPrint(),
            /* allowNullMethod */ true );
    }

    dwBoidsFilterOutput.stop();
}
```

### 23.6 算法步骤

1. **AvatarFilter output**:实体本身位置由父类处理;
2. **goal 计算**:goal = 实体位置;飞行状态下抬高到地形上方 20m;
3. **dTime 计算**:从上次 output 到现在的时间差;
4. **boidData_ 同步**:如果辅助模型数量变化,调整 boidData_ 数组大小;
5. **逐个 boid 更新**:调用 `BoidData::updateModel`;
6. **着陆检测**:如果 STATE_LANDING 且某 boid 到达 goal,触发 `boidsLanded` 脚本回调。

### 24.2 updateModel 完整算法

```cpp
// client/boids_filter.cpp:367-614
void BoidsFilter::BoidData::updateModel( const Vector3 & goal,
    IEntityEmbodiment * pCA, const BoidsFilter & filter,
    const float dTime, const float timeMultiplier, const int state,
    const float radius )
{
    BW_GUARD;
    // dTime 是 1/30 秒为单位
    const float DT = dTime * timeMultiplier;

    if (DT <= 0.0f) return;

    const BoidsFilter::Boids & boids = filter.boidData_;
    Vector3 deltaPos = Vector3::zero();
    Vector3 deltaDir = Vector3::zero();
    float count = 0;
    const float INFLUENCE_RADIUS_SQUARED =
        filter.influenceRadius_ * filter.influenceRadius_;
    const float INV_COLLISION_FRACTION =
        1.0f / ( 1.0f - filter.collisionFraction_ );
    const float GOAL_APPROACH_RADIUS_SQUARED =
        filter.goalApproachRadius_ * filter.goalApproachRadius_;
    const float GOAL_STOP_RADIUS_SQUARED =
        filter.goalStopRadius_ * filter.goalStopRadius_;

    // 1. 遍历所有其他 boid,计算分离/对齐/聚合
    for (uint i = 0; i < boids.size(); i++)
    {
        const BoidData & otherBoid = boids[i];
        if ( &otherBoid != this )
        {
            Vector3 diff = pos_ - otherBoid.pos_;
            float dist = diff.lengthSquared();
            dist = INFLUENCE_RADIUS_SQUARED - dist;

            if (dist > 0.f)   // 在影响半径内
            {
                dist /= INFLUENCE_RADIUS_SQUARED;
                count += 1.f;

                diff.normalise();
                float collWeight = dist - filter.collisionFraction_;

                if (collWeight > 0.f)
                {
                    collWeight *= INV_COLLISION_FRACTION;
                }
                else
                {
                    collWeight = 0.f;
                }

                if (dist - ( 1.f - filter.collisionFraction_ ) > 0.f)
                {
                    collWeight -= dist * ( 1.f - filter.collisionFraction_ );
                }

                Vector3 delta = collWeight * diff;
                deltaPos += delta;
                deltaDir += otherBoid.dir_ * dist;
            }
        }
    }

    // 2. 对齐:平均邻居方向
    if (count != 0.f)
    {
        deltaDir /= count;
        deltaDir -= dir_;
        deltaDir *= 1.5f;
    }

    Vector3 delta = deltaDir + deltaPos;

    // 3. 聚合:向 goal 移动
    Vector3 goalDir = goal - pos_;
    goalDir.normalise();
    goalDir *= 0.5f;
    delta += goalDir;

    // 4. pitch 调整(根据 delta.y)
    if (delta.y > 0.01f)
    {   // 太低,抬头
        pitch_ += filter.angleTweak_ * DT;
        if (pitch_ > 0.8f) pitch_ = 0.8f;
    }
    else if (delta.y < -0.01f)
    {   // 太高,低头
        pitch_ -= filter.angleTweak_ * DT;
        if (pitch_ < -0.8f) pitch_ = -0.8f;
    }
    else
    {
        pitch_ *= 0.98f;   // 阻尼
    }

    // 5. 速度:俯冲加速,爬升减速
    speed_ -= pitch_ * filter.pitchToSpeedRatio_;

    // 6. 速度阻尼向 normalSpeed
    speed_ = (speed_ - filter.normalSpeed_) * 0.99f + filter.normalSpeed_;

    if ( speed_ < filter.normalSpeed_ / 2 )
        speed_ = filter.normalSpeed_ / 2;
    if ( speed_ > filter.normalSpeed_ * 5 )
        speed_ = filter.normalSpeed_ * 5;

    // 7. yaw 调整
    Vector3 offset = delta;
    if (state != STATE_LANDING)
    {
        offset[Y_COORD] = 0.0f;   // 飞行时只考虑水平方向
    }

    delta = dir_;
    offset.normalise();
    float dot = offset.dotProduct( delta );

    // 直行时加速
    if (dot > 0.7f)
    {
        dot -= 0.7f;
        speed_ += dot * 0.05f;
    }

    // 计算偏航方向
    Vector3 vo = offset.crossProduct( delta );
    dot = (1.0f - dot)/2.0f * 0.07f;

    if (vo.y > 0.05f)
    {
        dYaw_ = (dYaw_*19.0f + dot) * 0.05f;
    }
    else if (vo.y < -0.05f)
    {
        dYaw_ = (dYaw_*19.0f - dot) * 0.05f;
    }
    else
    {
        dYaw_ *= 0.98f;   // 阻尼
    }

    yaw_ += dYaw_ * DT;
    roll_ = -dYaw_ * 20.0f * DT;   // 转弯时倾斜

    // 8. 设置模型矩阵
    Matrix m;
    m.setTranslate( pos_ );
    m.preRotateY( -yaw_ );
    m.preRotateX( -pitch_ );
    m.preRotateZ( -roll_ );

    dir_ = m.applyToUnitAxisVector( Z_AXIS );

    // 9. 着陆状态处理
    if (state == STATE_LANDING)
    {
        Vector3 goalDiff = pos_ - goal;
        float len = goalDiff.lengthSquared();

        if (len < GOAL_APPROACH_RADIUS_SQUARED)
        {
            dir_ = goalDir;   // 直接朝向目标
        }

        if (len > 0 && len < GOAL_STOP_RADIUS_SQUARED)
        {
            pos_ = goal;     // 到达目标
            speed_ = 0;
        }
    }

    // 10. 限制单帧飞行距离
    const Vector3 goalDiff = goal - pos_;
    const float goalDist = goalDiff.length();
    const float dirMultiplier = speed_ * DT;
    Vector3 flyVec = dir_ * dirMultiplier;
    if (dirMultiplier != 0.0f)
    {
        const float flyDist = flyVec.length();
        // 远离 goal 的 boid 单帧飞行距离更小
        const float maxFly = std::max(0.1f, radius - goalDist - 5.0f);

        if (flyDist > maxFly)
        {
            flyVec.normalise();
            flyVec *= maxFly;
        }
    }

    // 11. 移动 boid
    pos_ += flyVec;

    // 12. 超出 radius 时重置到中心
    if ( goalDist > radius )
    {
        if (ConnectionControl::instance().pReplayConnection() == NULL)
        {
            WARNING_MSG( "BoidData::updateModel: "
                "boid flew too far out: distance %f, max distance %f\n",
                goalDist, radius );
        }
        pos_ = goal;
        dir_ = goalDir;
    }

    // 13. 边界检查
    const float LIMIT = 100000.f;
    IF_NOT_MF_ASSERT_DEV( -LIMIT < pos_.x && pos_.x < LIMIT &&
        -LIMIT < pos_.z && pos_.z < LIMIT  )
    {
        ERROR_MSG( "BoidData::updateModel: Tried to move boid to bad "
            "translation: ( %f, %f, %f )\n", pos_.x, pos_.y, pos_.z);
        pos_ = goal;
        dir_ = goalDir;
    }

    // 14. 应用变换到模型
    pCA->worldTransform( m );
}
```

### 24.3 三大规则的具体实现

#### 24.3.1 分离(Separation)

```cpp
Vector3 diff = pos_ - otherBoid.pos_;   // 远离方向
float dist = diff.lengthSquared();
dist = INFLUENCE_RADIUS_SQUARED - dist;   // 越近,dist 越大

if (dist > 0.f)
{
    dist /= INFLUENCE_RADIUS_SQUARED;     // 归一化 0~1
    diff.normalise();

    float collWeight = dist - filter.collisionFraction_;
    if (collWeight > 0.f)
        collWeight *= INV_COLLISION_FRACTION;
    else
        collWeight = 0.f;

    // ...
    Vector3 delta = collWeight * diff;
    deltaPos += delta;
}
```

**含义**:`collWeight` 是分离强度。`dist > collisionFraction` 时(即距离小于 `(1 - collisionFraction) * influenceRadius`),才产生分离力,且越近力越大。

#### 24.3.2 对齐(Alignment)

```cpp
deltaDir += otherBoid.dir_ * dist;   // 累加邻居方向
// ...
if (count != 0.f)
{
    deltaDir /= count;          // 平均
    deltaDir -= dir_;            // 与自己的差
    deltaDir *= 1.5f;            // 放大
}
```

**含义**:把邻居方向加权平均,与自己方向的差作为对齐力。

#### 24.3.3 聚合(Cohesion)

```cpp
Vector3 goalDir = goal - pos_;
goalDir.normalise();
goalDir *= 0.5f;
delta += goalDir;
```

**含义**:BigWorld 的"聚合"是向"实体位置"(goal)移动,而不是向邻居中心移动。这是一种简化的聚合——所有 boid 都向同一个目标聚集。

### 24.4 速度与朝向的物理模型

#### 24.4.1 速度模型

```cpp
speed_ -= pitch_ * filter.pitchToSpeedRatio_;   // 俯冲加速
speed_ = (speed_ - filter.normalSpeed_) * 0.99f + filter.normalSpeed_;  // 阻尼
```

- pitch > 0(抬头)→ 减速;
- pitch < 0(低头)→ 加速;
- 速度向 normalSpeed 衰减(系数 0.99)。

#### 24.4.2 偏航模型

```cpp
Vector3 vo = offset.crossProduct( delta );   // 旋转轴
dot = (1.0f - dot)/2.0f * 0.07f;

if (vo.y > 0.05f)
    dYaw_ = (dYaw_*19.0f + dot) * 0.05f;
else if (vo.y < -0.05f)
    dYaw_ = (dYaw_*19.0f - dot) * 0.05f;
else
    dYaw_ *= 0.98f;

yaw_ += dYaw_ * DT;
roll_ = -dYaw_ * 20.0f * DT;   // 滚转与偏航反向(转弯时倾斜)
```

**偏航**:
- `vo.y` 是旋转轴的 y 分量,正负表示左转/右转;
- `dYaw_` 是带阻尼的偏航率(类似角速度);
- `dYaw_*19.0f` 是惯性(19份旧 + 1份新)。

**滚转**:
- `roll_ = -dYaw_ * 20.0f * DT`:左转时右倾(像飞机)。

### 24.5 着陆状态

```cpp
if (state == STATE_LANDING)
{
    Vector3 goalDiff = pos_ - goal;
    float len = goalDiff.lengthSquared();

    if (len < GOAL_APPROACH_RADIUS_SQUARED)
    {
        dir_ = goalDir;   // 接近时直接朝向目标
    }

    if (len > 0 && len < GOAL_STOP_RADIUS_SQUARED)
    {
        pos_ = goal;      // 到达,停止
        speed_ = 0;
    }
}
```

着陆状态下:
- 距离 < `goalApproachRadius_`(默认 10m):直接朝向目标;
- 距离 < `goalStopRadius_`(默认 1m):snap 到目标,速度归零。

如果有任何 boid 着陆,触发 `Entity.boidsLanded()` Python 回调,通常用于删除 boid 模型。

## 二十五、LinearPath 线性路径剖析

### 25.1 LinearPath 类

```cpp
// client/linear_path.hpp:13-27
class LinearPath
{
public:
    LinearPath( const Vector3& start, const Vector3& end );
    float length() const;
    Vector3 getPointAt( float t ) const;
    Vector3 getDirection( float t ) const;
    const Vector3& getStart() const;
    const Vector3& getEnd() const;

private:
    const Vector3 dir_;
    const Vector3 start_;
    const Vector3 end_;
};
```

`LinearPath` 是一个**参数化的直线段**:`P(t) = start + dir * t`,其中 `t ∈ [0, 1]`。

### 25.2 实现

```cpp
// client/linear_path.cpp:9-49
LinearPath::LinearPath( const Vector3& start, const Vector3& end ) :
    start_( start ),
    end_( end ),
    dir_( end - start )
{
}

float LinearPath::length() const
{
    BW_GUARD;
    return dir_.length();
}

Vector3 LinearPath::getPointAt( float t ) const
{
    BW_GUARD;
    return start_ + dir_ * t;
}

Vector3 LinearPath::getDirection( float t ) const
{
    BW_GUARD;
    return dir_;
}
```

实现极简:

- `dir_ = end - start`:方向向量(同时也是位移);
- `length()`:dir 的长度;
- `getPointAt(t)`:`start + dir * t`;
- `getDirection(t)`:返回 dir(常量,与 t 无关)。

### 25.3 设计意图

`LinearPath` 是 `PathSeeker` 的"路网单元"。一条复杂路径被分解为多个 `LinearPath` 串联:

```
P0─────P1─────P2─────P3─────P4
 │  L1   │  L2   │  L3   │  L4  │
                   ↑
              当前 t
```

每段 `LinearPath` 独立计算 `t ∈ [0, 1]`,到达 1 时切换到下一段。

### 25.4 与 AvatarFilter 的关系

`LinearPath` 与 AvatarFilter **没有直接关系**——它是 PathSeeker 用的,服务于"玩家点击地面 → 寻路 → 走过去"的场景,而不是网络位置平滑。

二者都是"位置插值"的工具,但应用场景不同:

| 工具 | 场景 | 数据源 |
|------|------|--------|
| AvatarFilter | 网络位置平滑 | 服务器 volatile 更新 |
| PathSeeker | 本地寻路跟随 | 寻路算法输出的路径点 |

### 26.2 setPath 实现

```cpp
// client/path_seeker.cpp:34-85
void PathSeeker::setPath( const PathPoints& pathPoints, float yawAtEnd )
{
    BW_GUARD;

    // 1. 失效旧路径
    t_ = 0.0f;

    // 2. 清空旧队列
    pathQueue_.clear();

    // 3. 把点序列转换为 LinearPath 队列
    PathPoints::const_iterator startPointItr = pathPoints.begin();
    PathPoints::const_iterator endPointItr = startPointItr + 1;
    for (;
        (startPointItr != pathPoints.end()) && (endPointItr != pathPoints.end());
        ++startPointItr, ++endPointItr)
    {
        const Vector3& end = *endPointItr;

        // 关键:start.y 设为 end.y,使路径"平坦"
        // 这样玩家在 XZ 平面上匀速移动,不会因 y 变化导致减速
        const Vector3 start( (*startPointItr).x, end.y, (*startPointItr).z );

        Path path( start, end );

        const float pathLength = path.length();
        if (pathLength <= MIN_DISTANCE_TO_POINT)
        {
            // 路径太短,跳过
        }
        else
        {
            pathQueue_.push_back( path );
        }
    }

    yawAtEnd_ = yawAtEnd;
}
```

**关键设计**:
- 把路径点序列转换为 `LinearPath` 队列;
- **强制每段路径在 XZ 平面上**(start.y = end.y),避免上坡时玩家减速;
- 过短的路径(< 2cm)被丢弃。

### 26.3 update 主循环

```cpp
// client/path_seeker.cpp:99-137
void PathSeeker::update( const MotionConstants& mc,
    const Vector3& useVelocity, float dTime,
    Angle& outNewHeadYaw, Vector3& outNewPos, SeekListener& callback )
{
    BW_GUARD;

    // 1. 更新参数 t
    this->updateParameter( useVelocity, dTime );

    // 2. 沿路径移动
    this->moveAlongPath( mc, outNewPos, callback );

    // 3. 转向
    this->turnToPath( mc, outNewHeadYaw );

    // 4. 检查是否完成
    if (this->isFinished())
    {
        outNewHeadYaw = yawAtEnd_ - mc.modelYaw;
        this->cancel( true, callback );
        return;
    }

    // 5. 调试绘制
    this->drawDebugPath( mc, outNewPos );
    this->drawDebugYaw( mc, outNewPos );
}
```

### 26.4 updateParameter 实现

```cpp
// client/path_seeker.cpp:267-287
void PathSeeker::updateParameter( const Vector3& velocity, float dTime )
{
    BW_GUARD;

    if (this->isFinished()) return;

    const float velocityLength = velocity.length();
    const Path& path = pathQueue_.front();
    const float pathLength = path.length();
    const float maxDisplacement = velocityLength * dTime;

    MF_ASSERT( pathLength > 0.0f );
    t_ += (maxDisplacement / pathLength);
}
```

**算法**:
- `maxDisplacement = velocity * dTime`:这一帧应该走的距离;
- `t_ += maxDisplacement / pathLength`:把距离转换为参数增量。

如果 `t_ > 1.0`,说明这一帧走过了头,会在 `moveAlongPath` 中切换到下一段。

### 26.5 moveAlongPath 实现

```cpp
// client/path_seeker.cpp:296-347
void PathSeeker::moveAlongPath( const MotionConstants& mc,
    Vector3& outNewPos, SeekListener& callback )
{
    BW_GUARD;

    if (this->isFinished()) return;

    const Path& path = pathQueue_.front();

    // 1. 还在当前段内
    if (t_ < 1.0f)
    {
        const Vector3 goal = path.getPointAt( t_ );

        // 检查是否离 path 太远(可能被卡住)
        Vector3 distance = outNewPos - goal;
        distance.y = 0.0f;
        if (distance.length() > MAX_DISTANCE_TO_POINT)
        {
            this->cancel( false, callback );   // 取消寻路
            return;
        }

        outNewPos.x = goal.x;
        outNewPos.z = goal.z;
    }
    // 2. 超过当前段末尾,切换到下一段
    else
    {
        outNewPos.x = path.getEnd().x;
        outNewPos.z = path.getEnd().z;

        t_ = t_ - 1.0f;

        if (!this->isFinished())
        {
            this->getNextPath( outNewPos, t_ );
            this->moveAlongPath( mc, outNewPos, callback );   // 递归
        }
    }
}
```

**算法**:
- `t_ < 1.0`:还在当前段,设置 outNewPos.x/z 为 path 上的点;
- `t_ >= 1.0`:到达段末,切换到下一段(`getNextPath` 弹出队首),剩余 t 递归处理;
- 卡住检测:如果 outNewPos 离 path 上的点超过 5m,取消寻路(失败)。

### 26.6 turnToPath 实现

```cpp
// client/path_seeker.cpp:355-368
void PathSeeker::turnToPath( const MotionConstants& mc, Angle& outNewHeadYaw )
{
    BW_GUARD;
    if (this->isFinished()) return;

    const Path& path = pathQueue_.front();
    const Vector3& targetDirection = path.getDirection( t_ );
    float targetYaw = atan2f( targetDirection.x, targetDirection.z );
    outNewHeadYaw = targetYaw - mc.modelYaw;
}
```

**算法**:
- 取当前 path 的方向(常量,与 t 无关);
- 用 `atan2` 转换为 yaw;
- 减去 modelYaw(模型当前的 yaw),得到相对偏航。

## 二十七、时间对齐系统

### 27.1 客户端/服务器时间同步

BigWorld 客户端的时间同步由 `BWConnection` / `BWServerConnection` 处理(详见专题7),不在 `time_globals.hpp` 中。`TimeGlobals` 类只负责"时间相关 watcher"的封装:

```cpp
// client/time_globals.hpp:13-25

{
private:
    TimeGlobals();

public:
    static TimeGlobals & instance();

    void timeOfDayAsString( BW::string newTime );
    float secondsPerGameHour() const;
    void secondsPerGameHour( float t );
};
```

### 27.2 TimeGlobals 的职责

`TimeGlobals` 只暴露两个 watcher:

| Watcher 路径 | 含义 |
|--------------|------|
| `Client Settings/Time of Day` | 当前游戏内时间(字符串,如 "12:30") |
| `Client Settings/Secs Per Hour` | 多少现实秒等于游戏内 1 小时 |

它**不涉及网络时间同步**,网络时间同步在 `BWConnection::clientTime()` 中。

### 27.3 网络时间同步

客户端的"游戏时间" `gameTime` 来自 `BWConnection::clientTime()`,这是经过 RTT 估算的"服务器当前时间"。

```cpp
// client/connection_control.cpp:1366
double ConnectionControl::gameTime() const
{
    return pConnection_ ? pConnection_->clientTime() : 0.0;
}
```

`BWConnection::clientTime()` 内部维护一个时间偏移 `serverTimeOffset_`,基于 RTT 估算:

```
clientTime = localTime + serverTimeOffset_
serverTimeOffset_ = (lastServerTime - lastLocalTimeAtReceive) + RTT/2
```

(详见专题7 Mercury 网络协议)

### 27.4 Filter 中的时间使用

Filter 使用的 `time` 参数有两个来源:

| 调用 | 来源 | 用途 |
|------|------|------|
| `input(time, ...)` | `BWConnection::lastMessageTime()` | 服务器消息到达时估算的"消息发出时的客户端时间" |
| `output(time, ...)` | `ConnectionControl::gameTime()` | 当前客户端 gameTime |

二者都是"客户端时间",通过 `serverTimeOffset_` 与服务器对齐。

### 27.5 时间对齐的影响

```
服务器时间线:    ─●────●────●────●────●────→
                 │    │    │    │    │
                 │    └包延迟(RTT/2)
                 │         │    │    │
                 ▼         ▼    ▼    ▼
客户端时间线:    ─●─────────●────●────●─→ (估算的"现在")
                 ↑         ↑    ↑    ↑
                 input.time      收到包时

                   ─────●────────────→ output.time = gameTime
                        ↑
                        Filter 查询历史的位置
```

`input.time` 是"包发出时的服务器时间"(估算),`output.time` 是当前 gameTime。两者都在同一个时间轴上,所以 `output.time - latency` 落在历史 input 范围内,插值正确。

### 27.6 时间回退的处理

如果服务器时间估算错误(例如 RTT 突然变化),可能出现 `input.time < storedInputs_[0].time_` 的情况(乱序)。AvatarFilter 通过 `if (time <= getStoredInput(0).time_) return;` 直接丢弃,保证历史时间单调。

### 28.1 完整的网络更新流程

### 28.2 isVolatile vs isTeleport

```cpp
// lib/connection_model/bw_entities.cpp:769-774
// Client-controlled entities cannot receive volatile position updates.
MF_ASSERT( !pEntity->isControlled() || !isVolatile );

// If controlled, this is a forced position, i.e. a physics correction
// If server-controlled, a non-volatile update is a teleport
const bool isTeleport = pEntity->isControlled() || !isVolatile;
```

| isControlled | isVolatile | isTeleport | 含义 |
|--------------|------------|------------|------|
| true | false | true | 客户端控制,服务器物理纠正 |
| false | true | false | 服务器控制,正常 volatile 更新 |
| false | false | true | 服务器控制,瞬移(非 volatile) |

**关键**:`isTeleport = true` 时,`onMoveInternal` 会调用 `pFilter_->reset(time)`,清空 AvatarFilter 历史。

### 28.3 乱序处理

```cpp
// lib/connection/avatar_filter_helper.cpp:313-316
if (time <= this->getStoredInput( 0 ).time_)
{
    return;
}
```

简单的"时间戳过滤"——任何比最新 StoredInput 旧的包都被丢弃。

**为什么这足够?** 因为 Mercury 网络层在传输时虽然可能乱序,但每个包带有时间戳。客户端只看时间戳,不关心到达顺序。这比"按到达顺序处理"简单且正确。

### 28.4 丢包处理

丢包的表现:
- 服务器发了 N 个包,客户端只收到 N-K 个;
- 收到的包时间戳不连续(中间有 gap)。

AvatarFilter 处理:
- 收到的包时间戳仍然单调(因为乱序过滤);
- `idealLatency_` 计算用最近 8 个**收到**的包(不含丢失的);
- 实际包间隔比服务器发送间隔大,`idealLatency_` 自动增大;
- `latency_` 缓慢追上,提供更多缓冲。

**效果**:丢包导致 latency 自动增大,实体平滑度保持,但视觉延迟增加。

### 28.5 onGround 占位处理

服务器在 volatile 更新中,如果实体"在地面",会把 y 设为约 -13000 的占位值。客户端见到这个值就采样地形高度。

```cpp
// lib/connection/avatar_filter_helper.cpp:330-331
this->resolveOnGroundPosition( storedInput.position_,
    storedInput.onGround_ );
```

`resolveOnGroundPosition` 在 §6.2.2 中已分析。

**为什么不直接发送真实 y?**
- 节省带宽(y 不用相对压缩);
- 服务器不需要做地形查询(由客户端做,服务器不知道客户端地形细节);
- 支持客户端本地地形 LOD(远端玩家看到的地形精度低)。

## 二十九、Filter 切换与状态保持

### 29.1 Filter 切换的触发

Filter 切换通过 Python 脚本触发:

```python
entity.filter = BigWorld.AvatarFilter()
# 或
entity.filter = BigWorld.DumbFilter()
```

这会调用 `PyEntity::filter` setter,最终走到 `BWEntity::pFilter(pNewFilter)`。

### 29.2 BWEntity::pFilter 实现

```cpp
// lib/connection_model/bw_entity.cpp:218-257
void BWEntity::pFilter( MovementFilter * pNewFilter )
{
    // 1. 没变化,直接返回
    if (pNewFilter == pFilter_)
    {
        return;
    }

    // 2. 清除 filter
    if (pNewFilter == NULL)
    {
        bw_safe_delete( pFilter_ );
        return;
    }

    // 3. 必须在 AoI 中
    IF_NOT_MF_ASSERT_DEV( isInAoI_ )
    {
        ERROR_MSG( "BWEntity::pFilter: Ignoring attempt to set a filter on "
            "entity %d which is not in our AoI\n", this->entityID() );
        return;
    }

    // 4. 状态拷贝
    if (pFilter_ != NULL)
    {
        pNewFilter->copyState( *pFilter_ );     // 关键
        bw_safe_delete( pFilter_ );
    }
    else
    {
        // 没有 filter 时,用当前位置初始化新 filter
        double time = this->pBWConnection()->clientTime();

        pNewFilter->reset( time );
        pNewFilter->input( time, spaceID_, vehicleID_, localPosition_,
            Vector3::zero(), localDirection_ );
    }

    pFilter_ = pNewFilter;
}
```

### 29.3 状态拷贝机制

`copyState` 调用链:

```
BWEntity::pFilter(pNewFilter)
       │
       │ pNewFilter->copyState(*pOldFilter)
       ▼
MovementFilter::copyState
       │
       │ if (tryCopyState(rOther)) return;
       │ // 子类多态
       ▼
   ┌───┴───────────────────────────────┐
   │                                   │
AvatarFilter::tryCopyState       DumbFilter (无重写)
       │                                   │
       │ dynamic_cast<AvatarFilter*>        │ return false
       │ 成功 → 拷贝 helper_                │
       │ 失败 → return false                 │
       │                                   │
       ▼                                   ▼
   拷贝成功                          走兜底:
   (完整历史)                       getLastInput() → input()
```

### 29.4 同类型切换

例如从 AvatarFilter 切换到 AvatarDropFilter(都是 AvatarFilter 子类):

```cpp
// AvatarDropFilter::tryCopyState
bool AvatarDropFilter::tryCopyState( const MovementFilter & rOtherFilter )
{
    const AvatarDropFilter * pOther = dynamic_cast<...>(&rOtherFilter);
    if (pOther == NULL)
        return this->AvatarFilter::tryCopyState( rOtherFilter );

    alignToGround_ = pOther->alignToGround_;
    groundNormal_ = pOther->groundNormal_;
    MF_VERIFY( this->AvatarFilter::tryCopyState( rOtherFilter ) );   // 链式调用
    return true;
}
```

链式调用:AvatarDropFilter::tryCopyState → AvatarFilter::tryCopyState → 拷贝 helper_。

### 29.5 异类型切换

例如从 DumbFilter 切换到 AvatarFilter:

1. `AvatarFilter::tryCopyState` 用 `dynamic_cast<AvatarFilter*>(&dumbFilter)` 失败(返回 NULL);
2. 返回 false;
3. 走兜底:`dumbFilter.getLastInput(...)` → `avatarFilter.input(...)`;
4. AvatarFilter 收到第一次 input,因为 `reset_ = true`,会 `resetStoredInputs`。

**效果**:历史只有 1 个 StoredInput,后续 input 才会逐渐填充 8 个。在头几秒内插值可能不太平滑,但不会出错。

### 29.6 切换时的 callback 处理

```cpp
// client/avatar_filter.cpp:263-309
bool AvatarFilter::tryCopyState( const MovementFilter & rOtherFilter )
{
    // ... 拷贝 helper_

    // 清空自己的 callback 链表
    while (callbackListHead_.getNext() != &callbackListHead_)
    {
        // ... delete
    }

    // 窃取对方的 callback
    ListNode * pNode = pOtherAvatarFilter->callbackListHead_.getNext();
    while (pNode != &pOtherAvatarFilter->callbackListHead_)
    {
        // ... 移到自己的链表
    }

    return true;
}
```

**窃取 callback 的前提**:旧 Filter 即将被销毁(`BWEntity::pFilter` 中 `bw_safe_delete(pFilter_)`)。这样不会出现"两个 Filter 同时拥有同一 callback"的双重释放。

## 三十、实体属性同步与 Volatile 更新分类

### 30.1 Volatile 成员的定义

实体的"volatile 成员"是位置 `(x,y,z)` 和朝向 `(yaw,pitch,roll)`,与普通属性的区别:

| 维度 | 普通属性 | Volatile 成员 |
|------|----------|---------------|
| 传输方式 | 可靠(基础属性) | 不可靠(UDP) |
| 频率 | 变化时 | 固定 tick(10Hz) |
| 距离感知 | 无 | AOI 距离调节(详见专题6) |
| 处理路径 | onProperty | onMoveFromServer → Filter |
| 客户端处理 | 直接赋值 | 通过 Filter |

### 30.2 Volatile 更新的网络消息

服务器通过 `AVATAR_UPDATE` 消息发送 volatile 更新,字段包括:

| 字段 | 含义 |
|------|------|
| position | 位置(可能 onGround 占位) |
| positionError | 误差盒三轴半径 |
| yaw / pitch / roll | 朝向 |
| vehicleID | 车辆 ID |
| spaceID | 空间 ID |
| isVolatile | 是否是 volatile(影响 isTeleport 判定) |

### 30.3 误差盒的来源

`positionError` 来自"玩家相对压缩":

- 离观察者近的实体,位置用 float32(高精度,误差 0);
- 离观察者远的实体,位置用更少的 bit,误差增大;
- 误差盒三轴半径不同(通常 x/z 大,y 小,因为远距离主要看水平位置)。

误差盒在 Filter 中的作用:
- `chooseNextWaypoint` 中钳制 Waypoint 位置到误差盒内;
- 避免插值结果偏到不合理的位置;
- 误差盒重叠时保持静止,避免无意义的微动。

### 30.4 Volatile 更新与 AOI 的协作

AOI 系统决定**何时发送** volatile 更新(详见专题6):

- 近端实体:10Hz;
- 中距离:1Hz;
- 远端:0.1Hz 或更少。

Filter 系统负责**接收后如何处理**:

- 近端:`idealLatency_` 小,响应快;
- 远端:`idealLatency_` 大,延迟大但稳定。

二者协作,实现"近端响应快,远端省带宽,但都平滑"。

### 30.5 onPositionUpdated 脚本回调

每次 Filter output 后,如果实体在世界中,会触发 `onPositionUpdated`:

```cpp
// lib/connection_model/bw_entity.cpp:382-385
if (this->isInWorld())
{
    this->onPositionUpdated();
}
```

`Entity` 重写此方法:

```cpp
// client/entity.hpp:106
void onPositionUpdated();
```

通常用于更新模型矩阵、触发脚本回调等。

### 30.6 实体属性同步的其他路径

除了 volatile 成员,实体还有:

| 数据类型 | 路径 | 与 Filter 关系 |
|----------|------|----------------|
| 基础属性 | onProperty | 无关,直接赋值 |
| 嵌套属性 | onNestedProperty | 无关 |
| 方法调用 | onMethod | 无关 |
| volatile 位置/朝向 | onMoveFromServer → Filter | **核心** |
| 服务器控制权 | onChangeControl | 影响 isTeleport 判定 |
| 物理纠正 | isPhysicsCorrected | 阻止 onMoveLocally |

## 三十一、性能分析

### 31.1 Filter 的 CPU 开销

#### 31.1.1 单次 output 开销

`AvatarFilter::output` 的主要开销:

| 步骤 | 复杂度 | 实测开销(估算) |
|------|--------|------------------|
| `helper_.output` | O(1) | ~5μs |
| `helper_.extract` | O(1) | ~2μs |
| `chooseNextWaypoint`(偶发) | O(NUM_STORED_INPUTS) = O(8) | ~10μs |
| `setSpaceVehiclePositionAndDirection` | O(1) | ~1μs |
| Callback 触发(偶发) | O(N_callbacks) | ~5μs/callback |
| `onEntityPositionUpdated`(AvatarDropFilter) | O(1) + collide | ~50μs |

总体:**单实体 AvatarFilter output ≈ 10~70μs**。

#### 31.1.2 单次 input 开销

| 步骤 | 复杂度 | 开销 |
|------|--------|------|
| 乱序检查 | O(1) | ~0.1μs |
| 环形后退 | O(1) | ~0.1μs |
| 写入 StoredInput | O(1) | ~0.5μs |
| `resolveOnGroundPosition` | O(1) + terrain | ~5μs |

总体:**单实体 input ≈ 6μs**。

### 31.2 大规模实体场景的 CPU 占用

假设场景中有 1000 个实体,60 FPS 渲染:

| 操作 | 频率 | 单次开销 | 总开销/秒 |
|------|------|----------|------------|
| AvatarFilter output | 60Hz × 1000 | 10μs | 600ms |
| AvatarFilter input(近端) | 10Hz × 100 | 6μs | 6ms |
| AvatarFilter input(远端) | 0.1Hz × 900 | 6μs | 0.54ms |

**注意**:output 是大头,600ms/秒意味着 60% 的 CPU 时间花在 Filter 上。这是 BigWorld 引擎的已知瓶颈,优化策略:

1. **远端实体降级**:远端实体用 DumbFilter,跳过 AvatarFilter 复杂逻辑;
2. **LOD 降低更新频率**:远端实体本来就低更新频率,搭配 latency 自适应;
3. **多线程**:Filter output 可以并行(目前是单线程);
4. **SIMD 优化**:lerp / crossProduct 等向量运算可 SIMD 化。

### 31.3 内存占用

| 数据结构 | 单实体占用 | 1000 实体 |
|----------|-----------|----------|
| `AvatarFilter` | ~700B | 700KB |
| `AvatarFilterHelper` | ~700B(包含 8 个 StoredInput) | 700KB |
| `AvatarFilterCallback` | ~64B(偶发) | <10KB |
| `BoidsFilter` 额外 | ~50B + N×40B boid | 看群大小 |
| `AvatarDropFilter` 额外 | ~16B | 16KB |

**总体**:`AvatarFilter` 每实体约 1.4KB,1000 实体约 1.4MB,完全可接受。

### 31.4 DogWatch 性能计数

BigWorld 内置 DogWatch 系统,Filter output 都有性能计数:

### 31.5 优化策略总结

| 策略 | 实现难度 | 收益 |
|------|----------|------|
| 远端实体用 DumbFilter | 简单(Python 配置) | 大幅降低 CPU |
| 简化 BoidsFilter(只对近端做完整 Boids) | 中等 | 中等 |
| 多线程 Filter output | 困难(需线程安全) | 大幅降低 CPU |
| SIMD 向量化 lerp | 简单 | 小幅降低 CPU |
| 减少 NUM_STORED_INPUTS | 简单(改常量) | 微小内存节省 |
| 异地实体延迟关闭 AvatarFilter | 简单 | 中等 |

## 三十二、边界情况处理

### 32.1 瞬移(传送)

**触发**:服务器发送 `isTeleport = true` 的位置更新,或服务器控制的实体收到非 volatile 更新。

**处理**:
```cpp
// lib/connection_model/bw_entity.cpp:898-909
if (isReset)
{
    pFilter_->reset( time );
}
pFilter_->input( time, ... );
if (isReset)
{
    this->applyFilter( time );   // 立即应用,不等下一帧
}
```

1. `reset(time)`:清空历史,设 `reset_ = true`;
2. `input(time, ...)`:因为 `reset_ = true`,触发 `resetStoredInputs`,所有 StoredInput 填为新位置;
3. `applyFilter(time)`:立即 output,实体瞬移到新位置。

**视觉效果**:实体瞬间出现在新位置,无平滑。

### 32.2 网络中断

**表现**:长时间没有 input,`storedInputs_` 中所有 StoredInput 的 time_ 都过期。

**处理**:
```cpp
// lib/connection/avatar_filter_helper.cpp:594-600
if (this->getStoredInput( 0 ).time_ < time)
{
    // 没有更多数据,原地站一帧
    previousWaypoint_ = nextWaypoint_;
    nextWaypoint_.time_ = time;
    return;
}
```

`chooseNextWaypoint` 中,如果最新 StoredInput 的 time_ 比 requested time 还旧,保持位置不变。

**视觉效果**:实体静止,等待网络恢复。

**latency_ 行为**:`idealLatency_` 保持上次值,`latency_` 也保持。网络恢复后,新 input 到达,`idealLatency_` 重新计算。

### 32.3 包丢失

**表现**:期望的 input 没到,`storedInputs_` 中有"空洞"(但因为环形缓冲,实际上没有空洞,只是某些 StoredInput 的 time_ 间隔变大)。

**处理**:`idealLatency_` 自动增大(因为 maxLatencyFrame 跨度变大),`latency_` 缓慢追上,提供更多缓冲。

**视觉效果**:实体平滑度保持,但视觉延迟增加。

### 32.4 包乱序

**表现**:后发的包先到。

**处理**:
```cpp
// lib/connection/avatar_filter_helper.cpp:313-316
if (time <= this->getStoredInput( 0 ).time_)
{
    return;   // 丢弃旧包
}
```

旧包直接丢弃,不影响历史。

**视觉效果**:无影响(乱序包被忽略)。

### 32.5 实体刚出现

**表现**:实体第一次进入 AoI,Filter 刚创建,`reset_ = true`。

**处理**:
1. `BWEntity::pFilter(pNewFilter)` 中:
   ```cpp
   // lib/connection_model/bw_entity.cpp:248-253
   double time = this->pBWConnection()->clientTime();
   pNewFilter->reset( time );
   pNewFilter->input( time, spaceID_, vehicleID_, localPosition_,
       Vector3::zero(), localDirection_ );
   ```
2. `reset(time)`:设 `reset_ = true`;
3. `input(time, ...)`:因为 `reset_ = true`,触发 `resetStoredInputs`,所有 StoredInput 填为当前位置。

**视觉效果**:实体立即出现在正确位置,无平滑。

### 32.6 实体上车/下车

**表现**:`vehicleID` 变化。

**处理**:`chooseNextWaypoint` 中通过 `changeCoordinateSystem` 把 Waypoint 转到新坐标系(详见 §15)。

**视觉效果**:实体平滑过渡,坐标系切换对玩家透明。

### 32.7 实体空间切换

**表现**:`spaceID` 变化(只有 player 实体可以)。

**处理**:
```cpp
// lib/connection_model/bw_entity.cpp:357-380
bool isSpaceChange = spaceID_ != spaceID && spaceID_ != NULL_SPACE_ID;
// ...
spaceID_ = spaceID;
// ...
if (isSpaceChange)
{
    MF_ASSERT( this->pVehicle() == NULL ||
        this->spaceID() == this->pVehicle()->spaceID() );
    this->triggerOnChangeSpace();
}
```

**视觉效果**:玩家瞬移到新空间(通常配合 loading screen)。

### 32.8 实体离开 AoI

**表现**:实体离开 AoI,Filter 被销毁。

**处理**:
```cpp
// lib/connection_model/bw_entity.cpp:735-753
void BWEntity::triggerOnLeaveAoI()
{
    // ... onLeaveAoI 回调
    isInAoI_ = false;
    this->pFilter( NULL );    // 销毁 Filter
    pVehicle_ = NULL;
}
```

`pFilter(NULL)` 中 `bw_safe_delete(pFilter_)` 销毁 Filter。

**Python 层**:`PyFilter::onFilterDestroyed` 被调用,`pAttachedFilter_ = NULL`,但 Python 对象继续存在(可复用)。

### 32.9 车辆未加载

**表现**:实体在车上,但车辆实体尚未加载到客户端。

**处理**:
```cpp
// client/avatar_filter.cpp:166-170
if (entity.waitingForVehicle())
{
    dwAvatarFilterOutput.stop();
    return;
}
```

`waitingForVehicle()` 返回 true 时,AvatarFilter 跳过 `onEntityPositionUpdated`(不调整位置)。`BWEntity::applyFilter` 会返回 false,实体被加入 `inconsistentEntities`,后续被移出世界。

### 32.10 误差盒突变

**表现**:服务器精度突然变化(误差盒大幅缩小或扩大)。

**处理**:`chooseNextWaypoint` 中检测重叠误差盒:

```cpp
// lib/connection/avatar_filter_helper.cpp:674-686
if ((newWaypoint.spaceID_ == currentWaypoint.storedInput_.spaceID_) &&
        (newWaypoint.vehicleID_ == currentWaypoint.storedInput_.vehicleID_) &&
        !almostEqual( newWaypoint.storedInput_.positionError_,
            currentWaypoint.storedInput_.positionError_) &&
        newWaypointBB.intersects( currentWaypointBB ))
{
    // 误差盒重叠 → 保持静止
    newWaypoint.position_ = currentWaypoint.position_;
}
```

**视觉效果**:避免无意义的微动。

## 三十三、与其他引擎对比

### 33.1 与 Unity Network Transform 的对比

Unity 的 `NetworkTransform` 组件(UNET/Netcode for GameObjects)提供位置同步:

| 维度 | Unity NetworkTransform | BigWorld AvatarFilter |
|------|------------------------|----------------------|
| 架构 | 组件,挂在 GameObject 上 | 独立 Filter 对象,挂在 Entity 上 |
| 插值方式 | 线性插值 / Snap | 历史缓冲 + 误差盒钳制 |
| 延迟自适应 | 无(固定 interpolation delay) | 有(latency 自适应) |
| 误差处理 | 无 | 误差盒钳制 |
| 坐标系 | 无(单一坐标系) | 自动 vehicle 变换 |
| 自定义 | 困难(组件内部) | 容易(继承 AvatarFilter) |
| 性能 | 简单,中等开销 | 复杂,略高开销 |
| 适用场景 | 小规模(几十实体) | 大规模(千实体) |

**BigWorld 优势**:误差盒、坐标变换、自适应延迟适合 MMOG;
**Unity 优势**:简单,易上手,适合小规模。

### 33.2 与 Unreal Network Interpolation 的对比

Unreal Engine 的 `USkeletalMeshComponent` / `Actor` 网络同步:

| 维度 | Unreal Network Interpolation | BigWorld AvatarFilter |
|------|------------------------------|----------------------|
| 架构 | Actor 属性 + RepNotify | Filter 对象 |
| 插值 | Mesh 位置插值 + Optional | AvatarFilter 历史插值 |
| 延迟 | 固定 NetUpdateFrequency | 自适应 latency |
| 平滑 | Linear / Smooth | Linear + 误差盒 |
| 预测 | Client-side prediction | 无(玩家用 PlayerAvatarFilter) |
| 回退 | Reconciliation | 无 |
| 自定义 | 中等 | 容易 |
| 适用场景 | 中等规模(百实体) | 大规模(千实体) |

**BigWorld 优势**:大规模、误差盒、自适应;
**Unreal 优势**:客户端预测(玩家手感好)、回退、动画集成。

### 33.3 与 Photon 的对比

Photon(Quantum)的同步:

| 维度 | Photon Quantum | BigWorld AvatarFilter |
|------|----------------|----------------------|
| 架构 | Deterministic lockstep | Snapshot interpolation |
| 模型 | 状态同步 + 全状态模拟 | 位置同步 + 客户端插值 |
| 延迟 | 一致性延迟(roll back) | 视觉延迟(latency) |
| 公平性 | 高(确定性) | 中(各客户端插值独立) |
| 复杂度 | 极高 | 中 |
| 带宽 | 低(只传输入) | 高(传位置) |
| 适用场景 | 竞技(FPS,MOBA) | MMOG |

**根本差异**:Photon 是"输入同步 + 确定性模拟",BigWorld 是"状态同步 + 插值"。前者适合需要公平性的竞技游戏,后者适合大规模、低带宽的 MMOG。

### 33.4 BigWorld Filter 系统的优劣分析

#### 33.4.1 优势

1. **大规模友好**:历史缓冲 + 自适应延迟,适合千实体场景;
2. **网络容错**:丢包、乱序、抖动都有处理;
3. **误差盒诚实**:不假装高精度,误差盒钳制保证视觉合理;
4. **坐标变换自动**:vehicle 切换对玩家透明;
5. **可扩展**:Python 包装 + C++ 继承,易扩展;
6. **时序回调**:AvatarFilterCallback 提供精准时序事件;
7. **可观测**:DogWatch + debugMatrixes + watcher,调试方便。

#### 33.4.2 劣势

1. **无客户端预测**:玩家位置也通过 Filter,响应感差(虽然有 PlayerAvatarFilter);
2. **无回退纠偏**:PlayerAvatarFilter 直接信任服务器,没有 client-side prediction + reconciliation;
3. **线性插值**:不使用样条,大角度转弯可能略生硬(可通过子类扩展);
4. **单线程**:Filter output 在主线程,大规模实体 CPU 瓶颈;
5. **复杂度高**:AvatarFilterHelper 算法复杂,理解和调试成本高;
6. **延迟感**:MMOG 的本质延迟 + Filter 延迟,总延迟可能 > 300ms,竞技场景不适用。

#### 33.4.3 设计哲学差异

| 流派 | 代表 | 核心思想 |
|------|------|----------|
| **状态同步 + 插值** | BigWorld | 传位置,客户端插值 |
| **状态同步 + 预测** | Unreal | 传位置,客户端预测 + 纠偏 |
| **输入同步 + 确定性** | Photon Quantum | 传输入,各自模拟 |
| **混合** | 现代 MMOG | 远端插值,近端预测 |

BigWorld 选择第一种,适合"服务器权威 + 大规模 + 低带宽"的 MMOG。

## 三十六、总结与最佳实践

### 36.1 核心设计总结

BigWorld Filter 系统的核心设计可归纳为五条:

1. **历史缓冲**:8 个 StoredInput 环形缓冲,提供冗余;
2. **延迟插值**:`outputTime = gameTime - latency_`,保证历史可用;
3. **自适应 Latency**:基于包间隔动态调整,既平滑又响应;
4. **误差盒钳制**:Waypoint 不超出网络层给出的误差范围;
5. **坐标变换自动**:vehicle 切换时 Waypoint 自动变换。

### 36.2 Filter 选择建议

| 场景 | 推荐 Filter | 理由 |
|------|-------------|------|
| 玩家自己 | PlayerAvatarFilter | 本地控制,无平滑 |
| 近端 NPC | AvatarFilter | 平滑,响应好 |
| 远端 NPC | AvatarFilter(可考虑 DumbFilter) | 平滑或省 CPU |
| 飞行群集(鸟/鱼) | BoidsFilter | 群集行为 |
| 导航网格 NPC | AvatarDropFilter | 落地 |
| UI 实体 | DumbFilter | 简单 |
| 调试实体 | DumbFilter | 简单可靠 |
| 瞬移后 | 自动处理(reset) | - |

### 36.3 性能优化建议

1. **远端实体降级**:AOI 远端实体用 DumbFilter,大幅降低 CPU;
2. **调整 latencyFrames**:对延迟不敏感的场景,可增大 `latencyFrames` 提升平滑度;
3. **关闭 AvatarFilter**:调试时设 `s_isActive_ = false`,对比效果;
4. **监控 DogWatch**:定期查看 Filter 性能,识别瓶颈;
5. **合理配置 BoidsFilter**:`influenceRadius_` 和 `radius_` 过大会导致 O(N²) 计算。

### 36.5 常见误区

1. **"AvatarFilter 使用 Catmull-Rom"**:实际上只用线性插值,但通过误差盒钳制达到接近样条的效果;
2. **"latency 越小越好"**:过小会导致没有历史可插值,反而抖动;
3. **"DumbFilter 永远不平滑"**:它仍有误差盒信任策略,避免不必要的跳变;
4. **"Filter 切换会丢失位置"**:有 `tryCopyState` 状态拷贝机制,同类型间可完整保留历史;
5. **"BoidsFilter 替代 AvatarFilter"**:BoidsFilter 继承 AvatarFilter,实体位置仍由 AvatarFilter 处理,Boids 只处理辅助模型。

### 36.6 与专题6(AOI)的关系

Filter 系统与 AOI 系统(专题6)紧密协作:

- AOI 决定**何时发送** volatile 更新;
- Filter 决定**如何处理** volatile 更新;
- AOI 的 UpdateScheme 影响更新频率,Filter 的 latency 自适应跟随;
- AOI 的 IDAlias 优化带宽,Filter 的误差盒诚实表达精度。

二者结合,实现"近端响应快,远端省带宽,但都平滑"的 MMOG 体验。

### 36.7 与专题13(客户端框架)的关系

Filter 系统是客户端框架(专题13)的子系统:

- `App` 提供 gameTime(`getGameTimeFrameStart`);
- `EntityManager` 持有 `BWClientFilterEnvironment`;
- `ConnectionControl` 调度 `BWEntities::tick`;
- `Entity` 是 `MovementFilterTarget` 实现。

理解 Filter 系统需要先理解客户端框架的整体结构。

### 36.8 总结

BigWorld Filter 系统是一个**为 MMOG 量身定制的网络位置平滑系统**。它通过历史缓冲 + 自适应延迟 + 误差盒钳制 + 坐标变换的组合,在大规模实体场景下实现了视觉平滑与网络容错的平衡。

虽然缺乏客户端预测和回退纠偏(不适合竞技场景),但对于 MMOG 这种"服务器权威 + 大规模 + 低带宽"的场景,Filter 系统的设计是恰当且优雅的。

理解 Filter 系统的内部机制,有助于:
- **调优**:合理配置 latencyFrames、minLatency;
- **扩展**:实现自定义 Filter 满足特殊需求;
- **调试**:通过 debugMatrixes、watcher 诊断位置异常;
- **优化**:识别 CPU 瓶颈,选择合适的降级策略。

## 附录 C:关键算法步骤速查

### C.1 AvatarFilterHelper::input

```
1. if (reset_): resetStoredInputs(); return;
2. if (time <= storedInputs_[0].time_): return;   // 乱序
3. currentInputIndex_ = (currentInputIndex_ + 7) % 8;
4. 写入 storedInputs_[0]
5. resolveOnGroundPosition(position, onGround)
6. gotNewInput_ = true; inputCount_++;
```

### C.2 AvatarFilterHelper::output

```
1. if (gotNewInput_):
   1.1 maxLatencyFrame = min(inputCount_, 8) - 1
   1.2 if (maxLatencyFrame > 0):
       - newestTime = storedInputs_[0].time_
       - olderTime = storedInputs_[maxLatencyFrame].time_
       - ratio = (maxLatencyFrame - latencyFrames) / maxLatencyFrame
       - idealLatency_ = time - lerp(ratio, olderTime, newestTime)
   1.3 idealLatency_ = max(idealLatency_, s_latencyMinimum_)
   1.4 gotNewInput_ = false
2. dTime = time - timeOfLastOutput_
3. dLatency = s_latencyVelocity_ * dTime * min(1, |idealLatency - latency|^s_latencyCurvePower_)
4. latency_ 朝 idealLatency_ 移动 dLatency(不超过)
5. timeOfLastOutput_ = time
6. outputTime = time - latency_
7. extract(outputTime, ...)
8. return outputTime
```

### C.3 AvatarFilterHelper::extract

```
1. if (!isActive()): 返回最新 StoredInput; return;
2. if (time > nextWaypoint_.time_): chooseNextWaypoint(time);
3. alpha = (time - prev.time) / (next.time - prev.time)
4. outputSpaceID/vehicleID = nextWaypoint 的
5. outputPosition.lerp(prev.pos, next.pos, alpha)
6. outputVelocity = (next.pos - prev.pos) / (next.time - prev.time)
7. yaw.lerp(prev.yaw, next.yaw, alpha)   // Angle::lerp 处理边界
8. pitch.lerp(prev.pitch, next.pitch, alpha)
9. roll = 0
```

### C.4 AvatarFilterHelper::chooseNextWaypoint

```
1. if (storedInputs_[0].time_ < time):
   1.1 previousWaypoint_ = nextWaypoint_
   1.2 nextWaypoint_.time_ = time
   1.3 return;   // 无 input,静止
2. 找 nextInputIndex(第一个 time_ > time 的 StoredInput)
3. newWaypoint 框架(基于 nextInput)
4. previousWaypoint.changeCoordinateSystem(nextInput 坐标系)
5. currentWaypoint.changeCoordinateSystem(nextInput 坐标系)
6. lookAheadPosition = lerp(prev.pos, current.pos, lookAheadInput.time 比例)
7. lookAheadPosition 钳制到 lookAheadInput 误差盒
8. if (新旧误差盒重叠): newWaypoint.position_ = current.position_;
   else: newWaypoint.position_ = lerp(current.pos, lookAheadPosition, 时间比例)
9. 钳制 newWaypoint.position_ 到 nextInput 误差盒
10. previousWaypoint_ = currentWaypoint;
11. nextWaypoint_ = newWaypoint;
```

### C.5 DumbFilter::input

```
1. if (time < time_): return;
2. time_ = time;
3. if (坐标系变化 或 误差精度相同):
   3.1 直接信任新输入
4. elif (新误差盒包含旧位置):
   4.1 不动,保留更精确的误差
5. else:
   5.1 信任新输入(可能跳变)
6. dir_ = dir;
```

### C.6 BoidsFilter::BoidData::updateModel

```
1. DT = dTime * timeMultiplier
2. 遍历其他 boid:
   2.1 if (在影响半径内):
       - 计算分离力(collWeight * diff)
       - 累加对齐力(otherBoid.dir_ * dist)
3. 对齐:deltaDir = (avg - dir) * 1.5
4. 聚合:goalDir = (goal - pos).normalise() * 0.5
5. pitch 调整(根据 delta.y)
6. 速度调整(pitch 影响 + 阻尼向 normalSpeed)
7. yaw 调整(根据 offset 与 dir 的叉积)
8. roll = -dYaw * 20 * DT
9. 设置模型矩阵
10. if (STATE_LANDING):
    - 接近时直接朝向目标
    - 到达时 snap 到目标
11. 限制单帧飞行距离
12. 移动 boid
13. 超出 radius 时重置
```

### C.7 PathSeeker::update

```
1. updateParameter(velocity, dTime):
   - t_ += velocity * dTime / pathLength
2. moveAlongPath(mc, outNewPos, callback):
   - if (t_ < 1): outNewPos.x/z = path.getPointAt(t_).x/z
   - else: 切换下一段,递归
   - 卡住检测(> 5m):cancel
3. turnToPath(mc, outNewHeadYaw):
   - targetYaw = atan2(dir.x, dir.z)
   - outNewHeadYaw = targetYaw - modelYaw
4. if (isFinished()): cancel(true)
5. drawDebug
```

## 附录 D:与 Catmull-Rom 的关系澄清

任务指引中提到"Catmull-Rom 样条插值",但经过完整源码审查,**BigWorld 14.4.1 的 AvatarFilter 实际上没有使用 Catmull-Rom 样条**,而是使用线性插值(lerp)。

### D.1 为什么会有这个误解

1. **历史原因**:早期 BigWorld 文档或宣传材料可能提到过 Catmull-Rom;
2. **概念混淆**:多采样点 + 误差盒钳制的视觉效果接近样条;
3. **类似系统**:其他引擎(如 Unity NetworkTransform)确实用 Catmull-Rom。

### D.2 实际的插值方式

```cpp
// lib/connection/avatar_filter_helper.cpp:537-538
outputPosition.lerp( previousWaypoint_.position_, nextWaypoint_.position_,
    proportionateDifferenceInTime );
```

这是标准的线性插值,不是 Catmull-Rom。

### D.3 如何实现真正的 Catmull-Rom

如果需要 Catmull-Rom 平滑,可以继承 AvatarFilter:

```cpp
class CatmullRomAvatarFilter : public AvatarFilter
{
protected:
    virtual void onEntityPositionUpdated( Entity & entity ) override
    {
        // 取 4 个相邻 StoredInput
        const auto & p0 = helper_.getStoredInput(2).position_;
        const auto & p1 = helper_.getStoredInput(1).position_;
        const auto & p2 = helper_.getStoredInput(0).position_;
        // p3 需要外推或用最新
        // ... Catmull-Rom 计算
    }
};
```

但这需要修改 `AvatarFilterHelper` 的访问权限,可能需要新的辅助方法。

### D.4 线性插值的优缺点

**优点**:
- 实现简单,性能好;
- 误差盒钳制方便(线性段易 clamp);
- 不会过冲(Catmull-Rom 在某些配置下会过冲)。

**缺点**:
- 大角度转弯时拐角明显;
- 速度在拐角处不连续(Catmull-Rom 是 C1 连续)。

BigWorld 选择线性插值是出于"简单 + 稳定"的考量,通过 8 个 StoredInput + 误差盒钳制,拐角被快速修正,视觉效果接近样条。

## 附录 F:版本与历史

BigWorld Engine 14.4.1 的 Filter 系统是多年演进的成果。主要变化:

- **早期版本**:`AvatarFilter` 直接持有 StoredInput,无 `AvatarFilterHelper`;
- **14.x 引入 Helper**:把算法抽到 `lib/connection/`,便于跨进程复用;
- **14.4.1 现状**:`AvatarFilterHelper` + `AvatarFilter` + `PyAvatarFilter` 三层架构,功能稳定。

未来可能的方向(推测):
- 引入客户端预测 + 回退纠偏;
- 多线程 Filter output;
- SIMD 向量化;
- 可选的 Catmull-Rom / Bezier 样条插值。
